# Оси вариантов площадки

Карточка `GET /api/v1/catalog/offers/{offerId}` содержит `variants: { groupId }`.
Группа продавца загружается до рендера отдельным запросом
`GET /api/v1/catalog/variants/{tenantId}/{groupId}` с контекстом покупателя.

Ответ:

```text
{
    groupId,
    options: [{ key, code, name, values: [...] }],
    items: [{ id, attrs: { "<ключ оси>": "<значение>" }, position,
              price, basePrice, available, inStock, image }],
    truncated
}
```

Оси берутся из первого подходящего предложения по позиции, затем id;
их порядок сохраняется в options. Предложения без вариантов или с другим
набором ключей осей пропускаются. Значения каждой оси идут в порядке позиций группы (position, затем id);
упорядочивание по схеме категории выполняет клиент. Дубликаты сочетаний остаются в items.
Потолок группы — 200 предложений; при truncated текущая карточка может
отсутствовать в items. Цены — числовые рубли в том же контексте, что карточка;
ответ имеет заголовки `X-Marketplace-Money-Unit: RUB` и `Cache-Control: private, no-store`.

На входе событий и сохранённых карточек принимаются axes[] и старая форма
axis + value, которая нормализуется в axes из одного элемента. Наружу —
только axes[]. Неизвестные поля игнорируются; смешанная и неполная старая
формы отклоняются. При приёме события Validate проверяет группу, системные
ключи, их уникальность, от одной до восьми осей и непустые скалярные значения
длиной до 1024 символов.
