# Контракт внутреннего API сервера для маркетплейса (PR-M1)

Маркетплейс спрашивает сервер установки о трёх вещах: актуальные цена и
наличие позиций, стоимость доставки по договору магазина и настройки участия
магазина в маркетплейсе. Здесь — ровно то, что ждёт клиент
`internal/infrastructure/platformapi`. Примеры взяты из его фикстур
`internal/infrastructure/platformapi/testdata`, тесты адаптера сверяют
запросы и разбор ответов с ними.

Сервер этих ручек пока не отдаёт: их добавляет PR-M1 в `proshop-server`,
по порядку S3 — после PR-08d (события реестра). До него перепроверка
корзины и подтверждение покупки отвечают `503 cart.seller_unreachable`,
расчёт доставки помечает всех продавцов `unavailable` с причиной
`seller_unreachable`, а синхронизация настроек оставляет участие магазинов
выключенным — предложения не видны в выдаче. Это ожидаемо.

## Общее

| Что | Как |
|---|---|
| Адрес | `PLATFORM_API_URL` + `/api/v1/internal/marketplace/tenants/{tenantId}` + путь ручки |
| Магазин | только в пути; `tenantId` экранируется как сегмент пути |
| Доступ | заголовок `x-internal-token: <SERVICE_TOKEN_MARKETPLACE>`, токен ≥ 32 символов; тот же заголовок, что у прочих внутренних ручек сервера |
| Формат | JSON, `Content-Type: application/json` у запросов с телом, `Accept: application/json` |
| Деньги | целые копейки (`int64`), без дробей и строк |
| Время | RFC 3339 с зоной (`2026-10-24T10:30:00Z`) |
| Успех | только `200`; тело ответа — до 4 МиБ |
| Отказ | любой другой код. Тело — общий формат ошибок сервера `{"ok":false,"message","status","code","items"}`; первые 512 байт пишутся в журнал. `403` с `code: "MARKETPLACE_DISABLED"` — магазин не участвует (ниже), остальное — сервер недоступен |
| Ожидание | `PLATFORM_API_TIMEOUT` (5s) на вызов; расчёт доставки — `QUOTE_TIMEOUT` (5s) на магазин |
| Повторы | клиент сам не повторяет; повторяет пользователь или следующий цикл синхронизации |

Неизвестные поля ответа игнорируются, отсутствующие считаются нулевыми.
Ответ, который не разбирается как JSON или нарушает ограничения ниже, —
`platform.invalid_response`; маркетплейс считает магазин недоступным.

### Магазин не участвует в маркетплейсе

Ручки для магазина, который не включил маркетплейс, отвечают `403`
(`settings/marketplace` вправе ответить и `200` с `"enabled": false` —
маркетплейс понимает обе формы одинаково):

```json
{"ok":false,"message":"Магазин не участвует в маркетплейсе","status":403,"code":"MARKETPLACE_DISABLED","items":null}
```

Маркетплейс считает это недоступностью магазина (`platform.marketplace_disabled`,
класс `unavailable`): покупатель получает «магазин не ответил», расчёт —
`seller_unreachable`. Кроме того, отказ на `items/check` или `delivery/quote`
ставит внеочередную сверку настроек этого магазина (задача outbox
`participant.settings.sync`, повтор до её разбора склеивается), а сверка,
получив тот же отказ на `settings/marketplace`, выключает участие и снимает
субсидию — предложения магазина уходят из выдачи, не дожидаясь планового
прохода.

## 1. Цена и наличие позиций

`POST /items/check`

Корзина перепроверяет позиции по запросу витрины (`POST /api/v1/cart/verify`),
покупка — при подтверждении (`POST /api/v1/checkout/{id}/confirm`). Один
запрос на магазин, магазины опрашиваются параллельно.

Запрос:

```json
{"items":[{"productId":"p1","quantity":2},{"productId":"p2","quantity":1}]}
```

Ответ:

```json
{"items":[
  {"productId":"p1","available":true,"price":199000,"availableQuantity":5},
  {"productId":"p2","available":false,"price":0,"availableQuantity":0}
]}
```

| Поле | Тип | Смысл |
|---|---|---|
| `productId` | строка | идентификатор товара из запроса |
| `available` | bool | товар существует, включён и продаётся сейчас |
| `price` | int64 ≥ 0 | цена за единицу, которую покупатель платит сейчас: с действующей акцией, если она есть |
| `availableQuantity` | int ≥ 0 | свободный остаток (за вычетом резервов) |

Как маркетплейс читает ответ:

- позиции нет в ответе или `available: false` — строка корзины помечается
  `unavailable`;
- `availableQuantity` меньше количества в корзине — `not_enough_stock`;
- цена отличается от сохранённой — цена в строке заменяется, строка
  помечается `price_changed`;
- отрицательные `price`/`availableQuantity` или `productId` не по формату —
  ответ не по контракту.

## 2. Стоимость доставки

`POST /delivery/quote`

`POST /api/v1/checkout/{id}/delivery/quotes` спрашивает каждого продавца
покупки: сколько стоит довезти его часть заказа выбранным перевозчиком в
выбранный пункт выдачи по договору магазина с перевозчиком.

Запрос:

```json
{"carrier":"cdek","pickupPointCode":"MSK123","city":"Город","items":[{"productId":"p1","quantity":2}]}
```

| Поле | Смысл |
|---|---|
| `carrier` | `cdek` или `yandex` — код перевозчика маркетплейса |
| `pickupPointCode` | код пункта у перевозчика (тот же, что в его справочнике) |
| `city` | город пункта из справочника маркетплейса |
| `items` | позиции этого продавца из покупки |

Ответ, доставка возможна:

```json
{"available":true,"cost":30000,"minDays":2,"maxDays":4,"expiresAt":"2026-10-24T10:30:00Z"}
```

Ответ, доставки нет:

```json
{"available":false,"reason":"carrier_not_connected"}
```

`cost` — чистая стоимость перевозки части заказа по договору магазина с
перевозчиком. Правила витрины магазина — бесплатная доставка от суммы,
скидки и прочие промо на доставку — на маркетплейсе не действуют и в `cost`
не входят. Участие продавца в доставке на маркетплейсе — только субсидия из
ручки 3, её применяет маркетплейс. Это требование к PR-M1.

Словарь `reason` закрыт, расширяется только через этот документ:

| `reason` | Кто ставит | Смысл |
|---|---|---|
| `carrier_not_connected` | сервер | у магазина нет этого перевозчика |
| `pickup_point_unavailable` | сервер | перевозчик не везёт в этот пункт |
| `no_rate` | сервер | тариф не рассчитан: вес, габариты или зона |
| `seller_unreachable` | маркетплейс | ответа нет или он не по контракту |

| Поле | Тип | Смысл |
|---|---|---|
| `available` | bool | магазин везёт этим перевозчиком в этот пункт |
| `reason` | строка | при `available: false` обязательна, одна из трёх серверных причин словаря |
| `cost` | int64 ≥ 0 | чистая стоимость перевозки по договору магазина, копейки |
| `minDays`, `maxDays` | int, `0 ≤ minDays ≤ maxDays` | срок в днях |
| `expiresAt` | RFC 3339, необязательно | до какого времени магазин держит цену |

Как маркетплейс читает ответ:

- срок цены — `min(expiresAt, сейчас + QUOTE_TTL)`; уже истёкший `expiresAt`
  при `available: true` — ответ не по контракту;
- субсидию продавца маркетплейс считает сам из настроек (ручка 3) и вычитает
  из `cost`: покупатель платит `cost − субсидия`;
- `available: false` — продавец помечается `unavailable` с причиной, покупку
  нельзя подтвердить с этим пунктом; причина пустая или не из словаря —
  ответ не по контракту;
- магазин не ответил или ответил не по контракту — `unavailable` с причиной
  `seller_unreachable`; такой расчёт повторяется при подтверждении.

## 3. Настройки участия магазина

`GET /settings/marketplace`

Маркетплейс сверяет настройки всех участников раз в `SETTINGS_SYNC_INTERVAL`
(5m) и хранит последние у себя. Флаг участия — третье условие видимости
предложений: участник включён оператором, магазин `active` в реестре, флаг
`enabled` магазина.

Ответ:

```json
{"enabled":true,"subsidy":{"enabled":true,"type":"percent","value":50,"maxAmount":30000}}
```

| Поле | Тип | Смысл |
|---|---|---|
| `enabled` | bool | магазин согласился продавать через маркетплейс |
| `subsidy` | объект или `null` | `null` или нет поля — субсидии нет |
| `subsidy.enabled` | bool | субсидия включена |
| `subsidy.type` | `fixed` или `percent` | фиксированная сумма или процент стоимости доставки |
| `subsidy.value` | int64 | `fixed` — копейки ≥ 0, `percent` — целое 0–100 |
| `subsidy.maxAmount` | int64 ≥ 0 | потолок субсидии в копейках; `0` — без потолка |

Субсидия не больше стоимости доставки и потолка; процент округляется к нулю
до копейки. Субсидия не по этим правилам — ответ не по контракту, сохранённые
настройки не меняются.

## Решения по вопросам к серверу

Закреплены оркестратором 2026-10-23 при приёмке недели 2.

1. `cost` — чистая стоимость по договору магазина, правила витрины не
   действуют; субсидию применяет только маркетплейс.
2. Словарь `reason` — `carrier_not_connected`, `pickup_point_unavailable`,
   `no_rate`, `seller_unreachable`; расширяется только через этот документ.
3. Магазин-неучастник — `403` с кодом `MARKETPLACE_DISABLED`; маркетплейс
   считает это недоступностью и запускает внеочередную сверку настроек.
4. PR-M1 появится на сервере после PR-08d (порядок S3); до него участие
   магазинов выключено — это ожидаемо.
