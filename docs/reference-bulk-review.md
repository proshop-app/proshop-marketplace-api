# Массовое решение по кандидатам справочника

Оператор может подтвердить или отклонить выбранных кандидатов одного
словаря одним запросом. Это явное действие пользователя: импорт и загрузка
списка сами по себе записи не подтверждают.

## Выбор и ревизия

`GET /api/v1/operator/reference/{dict}/entries?status=candidate` возвращает
`total` кандидатов, `revision` головы словаря и `ETag: "reference-N"`.
Количество и ревизия из этого ответа фиксируют основу выбора. `revision`
отдельной записи для batch-команды не используется.

Для строк или текущей страницы передаются конкретные `ids`. Для всех
кандидатов передаётся `allCandidates` и список исключённых id, без обхода
всех страниц в браузере. Пример точного выбора:

```http
POST /api/v1/operator/reference/d1/entries/review
If-Match: "reference-42"
Content-Type: application/json

{
    "status": "confirmed",
    "selection": {
        "mode": "ids",
        "ids": ["00000000-0000-0000-0000-000000000001"]
    }
}
```

Все кандидаты, кроме исключённых:

```json
{
    "status": "rejected",
    "selection": {
        "mode": "allCandidates",
        "excludedIds": ["00000000-0000-0000-0000-000000000002"]
    },
    "reason": "Проверено оператором"
}
```

Пустой `excludedIds: []` означает всех кандидатов. `ids` должен быть
непустым. Альтернативы не смешиваются; отсутствующий или `null` массив,
повторные id/JSON-ключи, неизвестные поля и неверные UUID отклоняются.
Только `confirmed` и `rejected` допустимы как целевой статус.

Оба режима обрабатывают только `candidate`. Все переданные id, включая
исключения, должны указывать на кандидатов этого словаря при той же голове.
Отсутствующая, чужая или уже обработанная запись отклоняет запрос целиком
с 409 `reference.selection_changed`. Confirmed, rejected, deprecated и
merged-записи не изменяются и в режиме всех кандидатов не выбираются.

## Атомарность и результат

Обязателен ровно один канонический заголовок `If-Match: "reference-N"`;
`N >= 0`, включая новый пустой словарь. Слабый ETag, список ETag и ревизия
записи без префикса недопустимы. Под блокировкой словаря голова сравнивается
до выбора id. Расхождение — 409 `reference.dictionary_changed`, без
автоматического повтора или пропуска изменившихся строк.

Успешный ответ:

```json
{
    "schemaVersion": 1,
    "dictionary": "d1",
    "revision": 47,
    "changed": 2204
}
```

Ответ также содержит новый ETag головы и `Cache-Control: no-store`.
`changed` — число действительно обработанных кандидатов. Если кандидатов
нет или все исключены, результат `changed: 0`, ревизия сохраняется.
После решения UI перечитывает список. При конфликте нужен новый выбор по
свежим `revision` и `total`; при сетевой ошибке сначала проверяется текущий
список, поскольку ответ мог потеряться после commit.

За один запрос допускается не более 10000 фактических целей и не более
10000 явных или исключённых id. Лимит целей считается после исключений.
Превышение даёт 400 `reference.limit_exceeded` целиком; список не обрезается.
JSON ограничен 512 КиБ. Общий контекст в 25 секунд начинается до разбора
тела и ожидания блокировки, сохраняя обычные HTTP/gateway таймауты.
При истечении бюджета — 503 `reference.review_timeout`; отменённая
транзакция не фиксирует ранее обработанные пачки.

Мутации проходят через доменный `ChangeStatus` и штатный `session.record`:
прямой и обратный образ журнала не более 500 записей и суммарно около
1 МиБ JSON на пачку; богатые записи делятся на меньшие пачки. Условный Save по
исходным статусу/версии, одна голова и одно событие outbox на всю транзакцию.
Любая ошибка, включая отказ поздней пачки, журнала, outbox или commit,
откатывает весь выбор. Отдельных SQL-обновлений статусов в обход домена нет.
Событие `catalog.reference.changed` сохраняет все виды следствий и полный
диапазон ревизий; списки id/ключей ограничены 1000, `truncated: true`
требует читать полную дельту снимка. Дельта содержит все изменённые записи.

Доступ — существующий операторский token или cookie с прежней CSRF-защитой.
Токен читателя не получает права на batch-команду. Подтверждение open-записей
попадает в обычную проекцию подсказок; closed-значения уже опубликованной
таксономии этой командой автоматически не перепубликуются.
