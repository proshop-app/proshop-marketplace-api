# Требования таксономии к словарям

Единственный источник заголовков и значений — uno-reference-data. Площадка содержит
код проверки и рабочий реестр PostgreSQL; данные таксономии остаются в
`internal/infrastructure/taxonomydata/data`.

Полный пакет `exports/marketplace-bootstrap.json` выпускается в uno-reference-data
по [контракту ImportPackage v2](reference-import.md). Он содержит все необходимые
заголовки, их настройки, записи и происхождение. Набор требуемых кодов вычисляется
из актуальных `attributes.yaml` и `dictionary-bindings.yaml`, а не дублируется здесь.

Для каждого `attribute.dictionary` проверяется вид словаря: `enum` требует closed,
строковый атрибут — open. Для каждого dictionary binding требуется open.
Пустой open допустим: заголовок обеспечивает публикацию привязки, но не полноту подсказок.
Closed требует confirmed-записей; все ключи `valuesMeta`, непустых `searchTermsByValue`
и примеры перечислений должны соответствовать подтверждённым значениям.
Кандидат не становится подтверждённым из-за привязки словаря к атрибуту.

Проверки качества конкретных данных выполняются в uno-reference-data:

- Полнота заголовков относительно актуальной таксономии, kind и settings.
- Нормализация, коллизии canonical/aliases, ограничения записей и происхождение.
- Цвет: 18 базовых значений и 22 оттенка перенесённого выпуска 3, корректные `baseColors`.
- Тип изделия: 154 перенесённых confirmed-значения, уникальность, отдельные понятия,
  алфавитный порядок и согласованный `metadata.order`.
- Проверка готового экспорта: сохранены статусы, связи и metadata исходников;
  исключение коллекции из кандидатов не должно удалять обязательный пустой open.

Чистая база: `make dev REFERENCE_DATA=../uno-reference-data` выполняет миграции,
импорт пакета и публикацию таксономии. Пакет и checkout обязательны.
На стенде оператор импортирует пакет до публикации. API на старте ничего не импортирует.
Проверка состояния базы нужна отдельно: наличие файла не доказывает успешное применение.
