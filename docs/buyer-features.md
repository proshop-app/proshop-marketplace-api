# Покупатель: профиль и сохранённые списки (R1)

Миграция `00041_buyer_features.sql`. Все `/api/v1/buyer/*` используют тот же
JWT identity-hub, что корзина. Идентификатор берётся только из контекста.
Ответы, включая ошибки авторизации, имеют `Cache-Control: private, no-store`.
Схемы и маршруты — в `api/openapi.yaml`.

- `GET/PATCH /api/v1/buyer/profile`: имя, регион, ПВЗ, настройки уведомлений,
  `alerts.priceDrops`. PATCH меняет только переданные поля, `null` очищает
  регион или ПВЗ; частичный объект notifications сохраняет остальные флаги.
  Имена регионов берутся из общего `pkg/regions` (ISO 3166-2, iso-codes),
  адрес ПВЗ — из справочника доставки по provider/code. Входное имя региона
  и адрес не считаются источником истины.
- `GET /api/v1/region`: сохранённый регион → регион сохранённого ПВЗ → IP → none.
  Доступен без входа. При `none` code/name равны null. Результат не записывается
  в профиль. Ручной cookie-регион остаётся ответственностью витрины.
- `GET/PUT/DELETE /api/v1/buyer/favorites[/{offerId}]`: лимит 500;
  GET принимает limit (1–500, по умолчанию 20) и offset (от 0).
  У снятого предложения сохраняется снимок, listed=false, inStock=false, checkoutAvailable=false, available=0.
- `GET/PUT/DELETE /api/v1/buyer/price-watches[/{offerId}]`: отдельный список,
  лимит 500. PUT принимает `{}` либо `{targetPrice: <копейки>}`. Повтор сохраняет
  исходную цену наблюдения и меняет цель; отсутствие цели/null очищает её.
  dropped означает currentPrice < priceAtWatch, при цели дополнительно currentPrice <= targetPrice.
  У снятого предложения currentPrice=null и dropped=false. Счётчик профиля
  считает достигнутые условия независимо от флага будущей рассылки.
- `GET/PUT/DELETE /api/v1/buyer/subscriptions/shops[/{tenantId}]`: лимит 500,
  повторные операции идемпотентны. GET возвращает публичные ShopCard.
  Шапка магазина получает число подписчиков SQL-агрегацией на чтении, для
  авторизованного — subscribed. Персонализированная шапка не кэшируется публично.

Списки изолированы по buyer_id, избранное и наблюдения — отдельные таблицы с
ключом (buyer_id, tenant_id, product_id). Проверка лимита и запись идут в UnitOfWork под
транзакционной блокировкой покупателя. Текущие цены/видимость читаются одной
пачкой из проекции предложений, без обращения к поиску или магазину на каждый товар.
Избранное, наблюдения, `dropped` и `alerts.priceDrops` выбирают ценовой профиль
покупателя тем же путём `catalog.PriceContexts`, что карточка каталога: из
`CatalogPricing` для публичных магазинов. Список магазинов читается отдельной короткой
транзакцией; запрос платформы выполняется без транзакции и блокировки покупателя.
В списках сбой источника возвращается вызывающему коду без подмены персональной цены.
GET и PATCH профиля при сбое возвращают `alerts.priceDrops: null` и пишут WARN;
изменения профиля сохраняются. Отсутствующий профиль
означает недоступное предложение. `priceAtWatch` — показанная покупателю цена
при первой подписке; повторный PUT её не меняет. SQL-счётчик получает карту
«магазин → ключ профиля» параметром и соединяет товар по `(tenant_id, product_id)`.
Снимок снятого предложения сохраняет `updatedAt`. PATCH возвращает профиль и
счётчик из той же транзакции, без повторного чтения в HTTP.
Профиль сохраняется условным UPDATE по исходной версии, конфликт типизирован.
Выбор ПВЗ при оформлении обновляет профиль в транзакции выбора ПВЗ (`Quote`).
Последующее подтверждение с прежним ПВЗ не перезаписывает профиль.

## Геолокация

`DADATA_API_KEY` необязателен. Без него IP-подсказка отключена (`source:none`,
если нет региона профиля/ПВЗ). Порт `ports.GeoIP`, адаптер DaData
`/suggestions/api/4_1/rs/iplocate/address`, таймаут 3 секунды. Redis использует
существующий клиент, TTL 24 часа, ключ — HMAC-SHA256 префикса сети (/24 IPv4, /64 IPv6). Кэшируются
также пустые результаты. Сбой провайдера включает общий `<prefix>geoip:down` на минуту, без IP.
Отмена контекста запроса не включает эту паузу.
Секрет `GEOIP_CACHE_SECRET` необязателен, но заданный должен содержать не менее 32 байт.
Без секрета отключён только кэш регионов; общая пауза провайдера действует.
В `Features.Region` анонимный `/region` ограничен 30 обращениями к провайдеру в минуту на сеть клиента.
Попадания в кэш и общая пауза лимит не расходуют; вошедший покупатель не лимитируется.
Сбой лимитера пишет WARN и не блокирует подсказку; ошибка провайдера
даёт none. IP и URL ошибки провайдера не передаются в журнал.

## Решения по неоднозначностям контракта

- В Offer поле available — количество. Признак продажи избранного — отдельное поле listed.
- Контракт не задаёт лимиты наблюдений/подписок: принято по 500, отдельные константы.
- Снятое наблюдаемое предложение имеет currentPrice=null, чтобы отсутствие цены
  не выглядело снижением до нуля.
- Справочник доставки содержал только ISO-коды. Добавлены имена из iso-codes
  в тот же пакет, без отдельного списка регионов покупателя.
- Скрытые магазины не возвращаются в GET подписок; запись подписки сохраняется,
  удалить её можно независимо от публичности магазина.

Интеграционные тесты PostgreSQL помечены `integration`, используют `pgtest`.
Живых вызовов DaData в тестах нет: ответы лежат в `testdata`, HTTP проверяется
через httptest.NewServer (общая обвязка newEnv).
