# Идентичность товара из схемы категории

Решение владельца 15.11.2026. Продолжает `docs/marketplace-variants.md`: этапы 3–4 того документа
(чужие продавцы и карточки моделей) строятся на правилах из схемы категории, а не на ключе в коде.

## Задача

Магазины заводят варианты по-разному: группой в админке (бренд + модель, для книг ISBN) или отдельными
товарами без группы — например, туфли каждого размера отдельной карточкой. Площадка должна сама:

1. сворачивать отдельные товары одного магазина одной модели в одну плитку с переключателем;
2. показывать, у каких других продавцов есть та же модель и какие у них варианты;
3. сравнивать цены одного и того же варианта у разных продавцов.

Какие атрибуты определяют модель и чем различаются варианты, в разных категориях разное: телефон —
бренд + модель, оси — цвет и память; обувь — бренд + модель, оси — цвет и размер; книга — ISBN, осей нет.
Это задаёт схема категории в таксономии, код только исполняет правило.

## Схема

В схему добавляется необязательный блок `identity`:

```yaml
phone:
  attributes: [brand, gtin, model, color, storage_capacity, ...]
  optional: [...]
  identity:
    model: [brand, model]             # одна модель у разных продавцов
    axes: [color, storage_capacity]   # чем различаются варианты модели
    exact: [gtin]                     # необязательный ключ точного варианта
shoe:
  identity:
    model: [brand, model]
    axes: [color, size_footwear_label]
book:
  identity:
    model: [book_isbn]
    axes: []
```

Проверки выпуска таксономии (`ValidateRelease`):

- каждый код из `model`, `axes`, `exact` есть в атрибутах схемы, без повторов и пересечений между списками;
- `model` не пуст; `axes` и `exact` могут быть пустыми;
- атрибуты `model` и `axes` обязательны в схеме (не входят в `optional`);
- ось — скалярный атрибут (перечисление, строка, число), не многозначный.

`identity` отдаётся в `GET /api/v1/taxonomy/schemas` и в схеме категории: админка магазина подсказывает
продавцу, какие поля склеивают его товары.

Обязательность новых атрибутов меняет публикацию у магазинов. Поэтому данные таксономии вводятся двумя
выпусками: сначала `identity` в режиме предупреждения (замечание публикации `identity_incomplete`, товар
публикуется), затем — после уведомления магазинов — атрибуты становятся обязательными.

## Ключи

Значения нормализуются по типу атрибута, без правил на категорию:

- словарный атрибут — id записи реестра (как бренд сейчас); неизвестное значение — ключа нет;
- строка — `reference.Key` без пробелов и дефисов;
- GTIN и ISBN — проверка контрольной суммы, приведение к 13 цифрам;
- число — каноническая запись.

- **Ключ модели** = `<схема>:` + нормализованные значения `model` в порядке схемы.
- **Ключ варианта** = ключ модели + значения `axes`; если заполнен `exact` — `exact:<значение>`.

Схема в ключе не даёт склеить планшет и телефон одной линейки. Пустое значение любого атрибута `model`
или `axes` — ключа нет, товар живёт как раньше. Нынешний расчёт (`gtin:` / `mpn:`) заменяется
расчётом по схеме; поля `modelKey`, `modelKeySource` остаются, добавляется `variantKey`.

## Этапы

Счётчик `sellersCount` в карточке и выдаче показывает число разных магазинов с видимым
предложением того же ключа модели, включая свой магазин; варианты магазина считаются один раз.
Без ключа или при сбое подсчёта поле отсутствует. Карточки не объединяются, выдача не схлопывается.

1. **Схема.** `identity` в формате, проверка выпуска, отдача в API таксономии, заполнение для схем
   телефонов, планшетов, часов, наушников, обуви, одежды, детской одежды, книг — в режиме предупреждения.
2. **Ключи в наблюдении.** Расчёт ключа модели и варианта по схеме при проекции (флаг
   `MARKETPLACE_MODEL_KEYS`), запись в индекс, метрики и `model-keys report` с разбивкой по схеме.
   Выдача не меняется.
3. **Сворачивание в магазине.** Поиск сворачивает предложения одного магазина с одинаковым ключом модели
   без ручной группы так же, как группу по `variantsId`; переключатель — по осям схемы. Ручная группа
   магазина главнее. Это меняет правило «ключ модели не участвует в collapse» из
   `marketplace-variants.md` — отдельный флаг поиска.
4. **У других продавцов.** `GET /api/v1/catalog/offers/{offerId}/alternatives`: предложения других
   магазинов с тем же ключом модели, их значения осей, цена и наличие; совпадение ключа варианта помечено.
   Переключатель вариантов между магазинами не переключает (решение 29.10): значение, которого нет у
   продавца, витрина показывает недоступным со ссылкой на предложение другого магазина.
5. **Витрина.** Блок «У других продавцов», пометки в переключателе, моки.

## Не делаем

- Не объединяем карточки и не переписываем данные продавцов.
- Не склеиваем по нечёткому совпадению названий.
- Не меняем корзину и оформление: заказ всегда у выбранного продавца.

## Перенос этапов 1–2 на поставку 11

Реализация перенесена из принятого diff PR #50 на master `ee3f945`.
В исходнике `schemas.yaml` блок `identity` и значение `identityWarnings`
наследуются независимо через `extends`. Явный `identity` заменяет весь блок,
без слияния списков; явный `identityWarnings: false` отключает унаследованный
режим предупреждений. Отсутствующее значение наследуется. В Go для этого
`identityWarnings` хранится как `*bool`; различие сохраняется в YAML и JSON.

Абстрактные схемы могут задавать идентичность. Проверка выполняется после
разворачивания атрибутов и `optional`, в том числе для абстрактных схем,
которые затем исключаются из снимка API. Списки идентичности и указатель
режима копируются, чтобы результат не изменял исходник или соседние схемы.

Все перечисленные ниже правила включены с `identityWarnings: true`.
Покрытие посчитано по листьям `categories.yaml` с учётом цепочки `extends`;
строки таблицы не пересекаются.

| Схема, задающая identity | model | axes | exact | Листовых категорий |
|---|---|---|---|---:|
| `phone` | `brand, model` | `color, storage_capacity` | `gtin` | 2 |
| `tablet` | `brand, model` | `color, storage_capacity` | `gtin` | 1 |
| `wearable` | `brand, model` | `color` | `gtin` | 2 |

В 331 категорию одежды входят 177 листьев раздела `clothing.children`.
Совместимая схема `clothing_kids` тоже наследует правило через `clothing`,
но непосредственно на неё в новой таксономии не ссылается ни один лист.
Размер `size_footwear_label` перенесён из четырёх дочерних схем в
`common_footwear`, чтобы правило базы проверялось по её собственным итоговым
атрибутам. Состав атрибутов и обязательность всех конкретных схем сохранены;
положение размера в порядке полей обуви изменилось.

Форматы идентификаторов: `gtin.format = gtin`, `book_isbn.format = isbn`.
Манифест выпущен командой `go run ./cmd/taxonomy manifest --release 11 --write`.

### Выпуск 15: обязательный вид товара

`product_type` — выбранное продавцом единственное значение закрытого enum.
Поле обязательно в схемах одежды и обуви, но не входит в идентичность
варианта (`variant: false`). Словарь выпуска 1 импортируется до таксономии
15. Публикация перепроверяет карточки: без типа они скрываются, пока продавец
не заполнит поле. Изменение не требует пересборки индекса; обновления
доставляются штатным outbox. Порядок поставки описан в `taxonomy-data.md`.
