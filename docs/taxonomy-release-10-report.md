## Совместимость и загрузка

Полная таблица 9 → 10: **795 unchanged, 26 renamed, 48 merge, 216 split**,
все 1085 исходных листьев учтены, удалений без адресата нет. Коды атрибутов
и ссылок на их словари не менялись; значения новых пулов не создавались.

HTTP принимает настоящие три файла, метаданные атрибутов и extends;
для замены categories введён явный query-флаг replaceCategories, описанный
в OpenAPI. Без него нельзя удалить лист или передать/изменить slug.
Сохранены If-Match и совместимость атрибутов; API возвращает развёрнутые схемы.

Админка принимает тот же формат, показывает метаданные в прежних таблицах,
считает удаляемые/перемещаемые листья и требует отдельное подтверждение.
После 409 подтверждение сбрасывается. Рабочий снимок обновлён скриптом;
большие списки используют штатный виртуализированный селект.

**Оператор:** резервная копия → импорт/проверка словарей → очистка устаревших
операторских привязок → attributes → schemas → categories с явным
подтверждением → 19 правил dictionaryBindings → переназначение/перепроверка
карточек → ожидание outbox и проверка выдачи. Точные маршруты и действия —
[инструкция загрузки](taxonomy-release-10-import.md).

**Блокер данных:** нужны все 196 словарей, 17 closed и 179 open;
в deploy/reference есть файлы 19, для **177** ссылок файлов здесь нет.
В том числе отсутствует closed target_gender. Точные обязательные confirmed,
наличие файлов и количество записей — [словарный отчёт](taxonomy-dictionaries-needed.md).
Состояние реестра стенда не читалось. Карточки с неизвестным старым кодом
сохраняют исходные данные, получают taxonomy.category_unknown и скрываются;
автоматического переназначения по таблице нет.

Все файлы меньше 2 МиБ; categories.yaml — около 1,34 МиБ. Для дальнейшего
роста предлагается отдельной поставкой согласованно поднять лимит API и
админки до 4 МиБ, а предел узлов — с 4096 до 8192, с проверкой производительности.
Формат и лимиты этой поставки не изменены.

API: go build ./..., go vet ./..., go test ./..., taxonomy check — успешно.
Новый HTTP-handler тест начинает со снимка 9 и загружает настоящие файлы 10;
проверяет закрытый словарь, откат версии при ошибке, подтверждение, CAS, лимит,
наследование и обратную выгрузку. Админка: lint, typecheck, 427 unit-тестов
в 67 файлах, production build — успешно. Есть предупреждение build о размере
общего чанка со снимком; это отдельная оптимизация.

Браузер Chromium: Desktop 1440×1000 и Mobile 390×844, три файла,
предпросмотр/отмена, ошибочный YAML, подтверждение клавиатурой; крупный
селектор — поиск, выбор и возврат фокуса. Сравнение 12 параметров закрытого
поля до/после совпало на обоих экранах; скриншоты просмотрены.

Не проверено: реальная БД и её блокировки/откат, импорт отсутствующих пулов,
применение на 150 карточках стенда, доставка outbox/Kafka и поисковый индекс,
полный набор e2e. Web не изменялся: ему нужно обновить снимок и показывать
унисекс-подборки по атрибуту одной карточки. Решений владельца по дереву не требуется.
