# Миграция 9 → 10

Поставка заменяет дерево целиком. Старые коды категорий и адреса разрешено
ломать по решению владельца; 150 стендовых товаров будут переназначены.
Карточки и словари этой работой не изменяются; снимок админки доработки 7 теперь требует повторного экспорта.

## Категории

Полная машинная таблица —
[`data/category-migration.yaml`](https://github.com/proshop-app/uno-reference-data/blob/132eccff41b0e91448e702c6ac75dd0ca8374df3/history/taxonomy/category-migrations.json):
каждый из 1085 листьев поставки 9 имеет ровно одну строку. Действия:
`unchanged` — сохранённый код и смысл вида, `renamed` — переименование, `merge` — общий
канонический адресат, `split` — выбор по виду, основному разделу или аудитории, `deleted` — удаление
с причиной и без адресата. В этой поставке удалений без адресата нет.

783 строк unchanged, 24 renamed, 45 merge, 233 split. При merge счётчик
означает число исходных листьев, а не число получившихся групп.
Перемещение или изменение схемы возможно и при прежнем коде: это не обещание
совместимости всех старых атрибутов карточки. Для split запрещено выбирать
первый элемент `to` автоматически. Старый общий лист «Туфли», например,
требует различить конструкцию шнуровки, союзки и подошвы.

Аудитория определяет верхние покупательские разделы носимых товаров;
неделимые виды и специальная обувь находятся в общем разделе. Один товар не
копируется в несколько разделов; веток унисекс нет. Пол независимо переносится
в target_gender только при достоверном исходном признаке; возраст — в min_age/
max_age по маркировке. Нельзя выводить числовой возраст из слова «детский».
Изменившиеся пути dictionaryBindings согласованы с новым деревом; поставка
передаёт явный список правил, не наследует правила удалённых веток.

## Атрибуты и значения

Глобальные определения прежних кодов сохранены с прежними типами, единицами
и базовыми словарями. Смешанные коды помечены deprecated и не входят в активные
схемы. Рабочего механизма псевдонимов атрибутов нет: миграция требует проверки
карточек и повторной публикации, а не переименования столбца словаря.

| Старый код / контекст | Новый код | Что делать со значениями и словарями |
|---|---|---|
| gender | target_gender + min_age/max_age | Новый closed-пул только пола; прежний gender оставить для истории. Возрастные формулировки разобрать, числовые границы не угадывать |
| compatibility | compatible_model, mount_standard | Модели и посадочные стандарты разделить; новые open-пулы и контекстные compat_* поставить отдельно |
| medical_application | body_area; функция задана листом | Анатомические области перенести в новый пул; текст медицинской задачи не выдавать за часть тела |
| skin_effect в уходе за волосами | hair_effect | Старый skin_effect сохраняется для кожи; подготовить отдельный пул эффектов волос |
| purpose | Вид изделия / профильное поле, например clothing_use или furniture_use | Не переносить общий свободный purpose во все схемы; прежний пул и значения не удалять |
| size | Маркировка соответствующего вида изделия | Сначала определить объект и систему; не копировать произвольный общий размер во все поля |
| size_clothing, size_kids_height | size_clothing_label + size_standard; wearer_height_min/max | Сохранить точную маркировку; единицы ростового измерения преобразовывать только при известном исходном формате |
| size_shoes_eu | size_footwear_label + size_standard | EU допустимо переносить из явно заданной старой системы; новый неизвестный числовой размер не считать EU автоматически |
| size_ring | ring_size_label + size_standard; ring_inner_diameter | Маркировку и измеренный внутренний диаметр разделить; стандарт и пересчёт подтвердить |
| age, pet_age | min_age/max_age, pet_life_stage | Интервалы человека и жизненный этап животного не объединять; новые значения — из поставки реестра |
| measurement_range | measuring_length_min/max, measuring_temperature_min/max, measuring_voltage_min/max | Определить величину и единицу, затем разобрать границы; исходную строку сохранить для разбора |
| resolution, camera_resolution | screen_width_px/height_px, camera_megapixels | Пиксели экрана и мегапиксели камеры не взаимозаменяемы |
| interfaces | interface_standard, connector и профильные поля | Не превращать список разных интерфейсов в одно словарное значение; без явного основного интерфейса поле не заполнять догадкой |
| frequency на радиоприборах | rf_frequency_min_hz/max_hz | Нужны границы основного радиодиапазона в Гц; единственное старое число не доказывает диапазон |
| focal_length | focal_min_mm/max_mm | Разобрать фиксированное значение либо реальные границы, привести единицу |
| wheel_bolt_pattern | wheel_hole_count, wheel_pcd_mm | Разобрать количество и диаметр окружности; прежнюю строку не выдавать за число |
| fishing_test | fishing_cast_min_g/max_g | Разобрать массу приманки в граммах; не подменять строй удилища |
| protection_class | ip_rating, electrical_safety, ppe_standard, child_seat_standard | Сначала определить стандарт и объект; один старый класс нельзя копировать во все системы |

Коды без изменения смысла сохраняются. В частности bag_fastener обозначает
основной механизм закрывания отделения сумки/футляра, его имя уточнено;
брелок вообще не получает это поле. bag_lock хранит механизм замка, tsa_lock —
отдельное логическое свойство сервисного открывания. Нельзя обучать одно
комбинированное значение вместо этих разных свойств.

Подключение новых открытых словарей существующим строкам разрешено процедурой
поставки 7: сырой текст остаётся строкой, новые ссылки не делают его enum.
Сами записи и ID словарей не переименовывать вслед за категориями.
Полный перечень требуемых пулов —
[taxonomy-dictionaries-needed.md](taxonomy-dictionaries-needed.md).

## Порядок оператора и потребители

1. Сохранить текущий снимок, назначения и словари. Установить отдельную
   поставку ссылочных пулов; новый target_gender должен быть closed,
   остальные новые строковые подсказки — open.
2. Проверить таблицу категорий и собственные dictionaryBindings, затем
   применить поставку с `--confirm-category-replacement` и актуальным CAS
   expected-version; см. [процедуру](taxonomy-releases.md).
3. Переназначить стендовые карточки по реальному виду; перенести типизированные
   значения по таблице выше, убрать исторические поля из нового блока.
   Сырые исходники оставить в магазине для проверки, не выдумывать пропуски.
4. Перепроверить карточки и дождаться обычной синхронизации поискового индекса.
   Указание неизвестной категории или исторического поля не становится алиасом.
5. marketplace-admin и web должны обновить снимки категорий, id/slug, схем,
   атрибутов и ETag; формы — использовать variant/deprecated и новые коды размеров
   и пола. Сервер магазина должен обновить кэш определения и источники подсказок.
   Старые адреса не получают автоматического 301 в этой работе.

Пакет в БД не применялся. Простой откат к 9 не может удалить добавленные
глобальные атрибуты: возврат дерева потребует корректирующей поставки и
обратного плана назначений, а не удаления словарных данных.

## Уточнения доработки 3

Таблица 9 → 10 включает новые покупательские виды: старые общие ботинки,
сапоги, туфли, куртки, костюмы, столы и другие широкие назначения разнесены.
Карнавальные костюмы перенесены из toys в clothing; лыжные ботинки разделены
на беговые и горнолыжные. Это ручной выбор по товару, не первый адрес split.

Переименование 244 отображаемых имён не означает переименование их кодов;
полные title омонима «Трубы» различают музыку и сантехнику. Новые группы
сохраняют ось деления. Это история до дополнения: актуальные аудиторные области
описаны ниже и заменяют прежний запрет.

Неизменные атрибуты и прежние словари сохранены. Новые смысловые коды:
fungus_species (мицелий, не вид растения), wedding_ring (обручальность),
watch_movement (механизм часов, не вид циферблата), flower_preservation
(обработка срезанных цветов), flower_stem_count (число стеблей, не упаковок), wine_bottle_count
(вместимость в стандартных бутылках 0,75 л), bread_loaf_mass_g и drying_tray_count.
Общий count упаковки не копируется в число поддонов, литры не вычисляются
из количества бутылок или массы выпечки. Если прежнее назначение достоверно
указывает обручальное кольцо, это основание для wedding_ring=true; иначе
обручальность не угадывается по металлу/форме.

После переназначения заполнить новые обязательные поля. Габариты чемодана
не вычислять из единственного размера либо наружного объёма. Материал обуви
и размерная маркировка обязательны; неизвестная система размера остаётся пустой.
Новые словарные ссылки и перечень обязательных — в сопровождаемых отчётах.

атрибутов не менялись. book_genre сохранён необязательным во всех книжных схемах;
его прежний пул не переименовывается вслед за категориями и не обязан совпадать
с их текстом. В books явная dictionaryBinding ведёт к тому же book_genre.

Новые поля: audience_age_group и book_edition_status — открытые пулы;
music_genre, film_genre, video_game_genre, poster_theme — отдельные смысловые пулы.

Оформление книги не мигрирует в жанр. Точное исходное значение сохраняют;
неизвестную аудиторию или жанр не угадывают. Для открыток повод отделён
от декоративной темы: craft_theme переносить в greeting_occasion только после
проверки, что исходное значение явно является поводом поздравления. У областей audience появился
nameScope; полный title/id/slug уникален. Потребителям обновить снимки и формы.

Широкие прежние ботинки/куртки остаются split даже при возврате их кода общему
остаточному виду: новые именованные конструкции не пропадают из адресатов.
Переиспользование адреса не означает автоматическое сохранение назначения.

## Доработка 6: единообразные аудитории

Общей детской обуви нет. Прежние общие детские адреса заменены парами
применимых девичьих/мальчиковых видов; основной адрес выбирают по изготовителю
или явно фиксируют как выбор продавца для унисекс. Не переносить его первым
элементом split. Тип, единица, словарь и необязательный пол атрибута не меняются.

Носимые виды аксессуаров/украшений и парфюмерия снова имеют аудитории.
accessories.wallets и jewelry.rings, например, разнесены в полные аудиторные
наборы; ключницы/визитницы и детали сохраняют общие адреса. Точные цели — в
машинной таблице. Контекстные dictionaryBindings остаются на прежних корнях,
поэтому источники словарей не осиротели.

Проверочный план 38 унисекс-карточек вынесен в demo-shops/taxonomy-fit и не
является изменением исходных карт магазинов. Перед фактическим импортом нужен
явный выбор продавца по этим карточкам. Показывать товар в других разделах
web должен по target_gender; одно назначение категории сохраняется.

## Дополнение доработки 9

Рабочие куртки, брюки, полукомбинезоны, халаты и сигнальная одежда 9 больше
не сводятся к обычному гардеробу или одному комплекту. Школьный общий код
разнесён на предметы двух детских аудиторий. Общие брюки, пижамы и джинсы
учитывают добавленные бриджи/капри, кигуруми и джеггинсы. `garden.sauna-hats`
ведёт в единственный `textiles.sauna-hats`. Для нового короткого младенческого
комбинезона используется `clothing.baby-short-rompers`: старый код
`clothing.baby-rompers` 9 обозначал ползунки/слипы и сохраняет прежнюю миграцию.

Добавлены два логических признака материнства и четыре числовые границы
измерения грунта, а также номинальная выходная мощность инвертора. Старые коды атрибутов, единицы и словари не менялись;
перенос словарных значений не требуется. Два логических признака и четыре диапазона необязательны; `ac_output_w` обязателен у аккумуляторной электростанции. Словари
им не нужны. Материнство не выводится из пола, а диапазон прибора — из
текущего показания грунта. Новый обязательный объём цилиндров малых двигателей
использует прежний числовой код `engine_volume_cm3`, без нового словаря.

Из общих обогревателей, посуды, готовых блюд и лодок также выделены именованные
виды: список `to` учитывает эти разделения. Новые школьные трикотажные предметы
включены в миграцию общего школьного раздела и соответствующих общих предметов.
При переносе в аккумуляторную электростанцию нужны паспортные `battery_energy`
и `ac_output_w`: потребление `power` не является выходом, а мА·ч нельзя считать
Вт·ч без напряжения. Для электротекстиля добавляются габариты полотна.
