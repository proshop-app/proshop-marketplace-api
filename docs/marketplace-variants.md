# Варианты и наблюдение за моделями: этапы 1–2

Группа вариантов ограничена одним продавцом. Ключ модели никогда не участвует
в collapse, ранжировании, фасетах, цене, корзине или оформлении.

## Контракты

Событие товара содержит `variants: { groupId, axis: { key, code, name }, value,
position }` либо явный `null`. Ось — единственная системная характеристика
`platform.<code>`, значение — скаляр. Отсутствующее поле поддерживает старого
издателя; явный null скрывает только переключатель. Площадка всегда
сворачивает по `variantsId`, независимо от подходящей оси. Магазинная группа
и её режим показа сохраняются.

Поиск принимает защищённый `POST /v1/internal/marketplace/group` с `tenantId` и
`groupId`. Ответ
содержит до 200 видимых предложений и `truncated`. Используется публичная цена
канала, как у текущего предложения; чужой продавец и другая
ось исключаются. Значения перечисления следуют порядку таксономии, остальные
— позиции в группе и идентификатору. Дубли значений остаются в API с
`duplicate`; интерфейс выбирает первый в наличии.

`GET /api/v1/catalog/offers` принимает `tenant` вместе с `groupId`, чтобы
открыть все позиции большой группы. Обычная выдача при включённом collapse
считает группы, включая фасеты. Без группировки сохраняется прежний фильтр
`listed`. Варианты без остатка остаются доступными по ссылке.

## Таксономия

Поставка 2: 29 направлений, 1204 категории, 1047 листьев, 142 схемы,
219 атрибутов, 167 значений. Добавлены GTIN и метаданные образцов цвета.
Согласованные перечисления: одежда XS, S, M, L, XL, XXL, 3XL, 4XL;
обувь EU 35–48 с шагом 0.5; детский рост 50–170 с шагом 6;
кольца 14–24 с шагом 0.5. Детская одежда и кольца имеют отдельные схемы.
Старый `size` сохранён, автоматического преобразования данных продавца нет.

По решению владельца неверный GTIN блокирует сохранение товара и публикацию
с причиной `gtin_invalid`; импорт отклоняет строку с `gtin-invalid`.
Неподходящая ось даёт предупреждение `variant_axis_unsupported`, многозначная —
`variant_axis_multivalue`. Группа остаётся одной плиткой без переключателя.

## Ключ модели

`MARKETPLACE_MODEL_KEYS=false` по умолчанию. При включении индексатор читает
актуальную схему категории через порт таксономии. `identity.model` определяет
модель, `identity.axes` — вариант, `identity.exact` — точный идентификатор.
Без identity оба ключа пусты. Источник непустого ключа — `modelKeySource=identity`.

Ключ модели: `<schema>:<model values>`, ключ варианта: ключ модели и значения
осей через `:`. Заполненный и корректный exact заменяет ключ варианта на
`exact:<exact values>`, но не отменяет проверку полноты model и axes.
Любое пустое, невалидное или неизвестное словарное значение model/axes
оставляет оба ключа пустыми. Порядок значений задаёт схема; разделители в
значениях экранируются через percent-encoding.

Словарные значения разрешаются в канонические id реестра (включая бренд,
цвет и размеры); ошибка или отсутствие точного совпадения оставляет ключ
пустым. Таймаут каждого разрешения — 300 мс. Строки нормализуются через
`reference.Key` без пробелов и дефисов, числа — в каноническую запись.
Правило идентификатора задаёт `format` атрибута (`gtin` или `isbn`),
независимо от его кода. Без format применяется нормализация по типу/словарю.
ISBN-10 с корректной контрольной суммой преобразуется в ISBN-13; ISBN-13
проверяется с префиксом 978/979. Пробелы и дефисы ISBN допускаются.
GTIN проверяется через `ParseGTIN`: 8/12 дополняются до 13 цифр; у GTIN-14
убирается только нулевой индикатор. Ненулевой индикатор нельзя без потери
свести к 13 цифрам, поэтому такой exact не используется.

Поставка таксономии 10 задаёт identity восьми схемам. `identityWarnings: true`
— явное исключение из проверки обязательности model/axes в переходном
выпуске. Списки optional не изменены. Без этого параметра выпуск требует
обязательные model/axes. Пустое значение необязательного поля identity даёт
замечание `identity_incomplete` с кодом атрибута и не блокирует публикацию;
существующие обязательные поля и остальные проверки остаются в силе.

| Схема | Модель | Оси | Exact |
|---|---|---|---|
| phone, tablet | brand, model | color, storage_capacity | gtin |
| wearable, headphone | brand, model | color | gtin |
| shoe | brand, model | color, size_shoes_eu | gtin |
| clothing | brand, model | color, size_clothing | gtin |
| clothing_kids | brand, model | color, size_kids_height | gtin |
| book | book_isbn | нет | нет |

Используются реальные специализированные размеры схем; старое поле `size`
не преобразуется. У часов и наушников нет размерной оси в текущей схеме.
ISBN определяет издание книги без дополнительных осей.

Миграция 00029 хранит вычисляемые `model_key` и `model_key_source` из JSON
карточки. Миграция 00049 добавляет аналогичную колонку `variant_key`.
JSON, колонки и документ индекса содержат оба ключа. Reindex пересчитывает
ключи после изменения схем и слияний реестра; отключение флага и reindex
очищают оба ключа. Расчёт и вызовы реестра выполняются вне транзакции
проектора; версионный конфликт пропускает устаревший снимок, актуальное
событие досчитывает ключ.

Диагностическую статистику пересчитывает один фоновый исполнитель раз в 30 минут.
Бюджет чтения — 60 секунд; при ошибке остаётся последний успешный срез,
ошибка записывается в журнал. Учёт изменений для отчёта не добавляет записей
при обработке событий товаров. Свежий ручной срез доступен командой ниже.
Метрики:
`marketplace_model_key_offers{source}`, `marketplace_model_key_shared{source}`,
`marketplace_model_key_offers_by_direction{direction,source}`,
`marketplace_model_key_offers_by_schema{schema,source}` и
`marketplace_identity_incomplete_share{schema}`. Ошибки реестра и конфликты
считают прежние `marketplace_model_key_resolve_failures_total` и
`marketplace_model_key_conflicts_total`.

`marketplace model-keys report --out report.json` выгружает количества,
доли (0–1), направления, схемы и до 200 примеров совпавших ключей с полными
исходными атрибутами и variantKey. В counts пустые direction и schema
означают весь каталог; непустое поле определяет срез. `identityIncomplete`
— число предложений с замечанием, `identityIncompleteShare` — их доля
от всех предложений данного среза (суммируется по source).
Метрика доли суммирует источники для каждой схемы. Файл создаётся с правами 0600.
Выдача, поиск и сворачивание продолжают работать по прежним правилам.

## Порядок поставки и откат

1. Выпустить `@proshop-app/types`, `@proshop-app/helpers` и `@proshop-app/enums`
   из psdeps, закрепить версию в server/admin и обновить lock-файлы.
   Для этой поставки опубликована версия `0.73.0` (deps PR #68).
2. Применить миграции marketplace и поставку таксономии с проверкой ожидаемой
   версии. Серверный сид версии 3 досевает общие атрибуты штатной командой.
3. Выпустить search и сразу включить `SEARCH_MARKETPLACE_COLLAPSE=true`,
   **до** выката marketplace с `listed = visible`. Поиск дополняет mappings
   существующих поколений; пропавшие партиции не восстанавливаются пустыми.
4. Выпустить серверный издатель, затем marketplace и витрину. Миграция групп
   не нужна: группа без оси сворачивается по `variantsId`, без позиции
   состав упорядочивается по id. Перестроить индекс marketplace.
5. Проверить количество плиток, фасеты и состав карточек при уже включённом
   collapse. Отдельно включить `MARKETPLACE_MODEL_KEYS=true` и выполнить
   reindex для заполнения ключей старых предложений.

Откат группировки: выключить SEARCH_MARKETPLACE_COLLAPSE. Откат наблюдения:
выключить MARKETPLACE_MODEL_KEYS и выполнить reindex для очистки ключей.
Новые поля можно оставить; при удалении миграции сначала откатить использующий
колонки код и задания метрик. Таксономия откатывается штатной командой новой
версией; данные продавцов не переписывались.

Кластеры, production и включение флагов этой работой не затрагивались.
Публикация shared-пакетов выполнена отдельным разрешённым слиянием deps #68. Этапы 3–4 (чужие продавцы и общие карточки моделей) не входят.
