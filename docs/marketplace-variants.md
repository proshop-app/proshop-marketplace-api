# Варианты и наблюдение за моделями: этапы 1–2

Группа вариантов ограничена одним продавцом. Ключ модели никогда не участвует
в collapse, ранжировании, фасетах, цене, корзине или оформлении.

## Контракты

Событие товара содержит `variants: { groupId, axis: { key, code, name }, value,
position }` либо явный `null`. Ось — единственная системная характеристика
`platform.<code>`, значение — скаляр. Отсутствующее поле поддерживает старого
издателя; явный null скрывает только переключатель. Площадка всегда
сворачивает по `variantsId`, независимо от подходящей оси. Магазинная группа
и её режим показа сохраняются.

Поиск принимает защищённый `POST /v1/internal/marketplace/group` с `tenantId` и
`groupId`. Ответ
содержит до 200 видимых предложений и `truncated`. В карточке выбирается тот
же ценовой профиль, что и у текущего предложения; чужой продавец и другая
ось исключаются. Значения перечисления следуют порядку таксономии, остальные
— позиции в группе и идентификатору. Дубли значений остаются в API с
`duplicate`; интерфейс выбирает первый в наличии.

`GET /api/v1/catalog/offers` принимает `tenant` вместе с `groupId`, чтобы
открыть все позиции большой группы. Обычная выдача при включённом collapse
считает группы, включая фасеты. Без группировки сохраняется прежний фильтр
`listed`. Варианты без остатка остаются доступными по ссылке.

## Таксономия

Поставка 2: 29 направлений, 1204 категории, 1047 листьев, 142 схемы,
219 атрибутов, 167 значений. Добавлены GTIN и метаданные образцов цвета.
Согласованные перечисления: одежда XS, S, M, L, XL, XXL, 3XL, 4XL;
обувь EU 35–48 с шагом 0.5; детский рост 50–170 с шагом 6;
кольца 14–24 с шагом 0.5. Детская одежда и кольца имеют отдельные схемы.
Старый `size` сохранён, автоматического преобразования данных продавца нет.

По решению владельца неверный GTIN блокирует сохранение товара и публикацию
с причиной `gtin_invalid`; импорт отклоняет строку с `gtin-invalid`.
Неподходящая ось даёт предупреждение `variant_axis_unsupported`, многозначная —
`variant_axis_multivalue`. Группа остаётся одной плиткой без переключателя.

## Ключ модели

`MARKETPLACE_MODEL_KEYS=false` по умолчанию. При включении сначала проверяется
GTIN (8/12/13/14 цифр, контрольная цифра); 8 и 12 дополняются слева до 13.
Ключ имеет вид `gtin:<цифры>`. Иначе используется канонический id бренда из
реестра и нормализованный артикул производителя: `mpn:<brand-id>:<part>`.
Неизвестный бренд или ошибка разрешения оставляют ключ пустым; публикация
не падает. Таймаут разрешения — 300 мс. Reindex пересчитывает ключи, в том
числе после слияния брендов и при отключении флага.

Миграция PostgreSQL 00029 добавляет вычисляемые колонки `model_key` и
`model_key_source` из JSON карточки и частичный индекс. JSON и колонки
не могут разойтись. Статистика обновляется каждые 10 минут:
`marketplace_model_key_offers{source}`, `marketplace_model_key_shared{source}`,
`marketplace_model_key_offers_by_direction{direction,source}`;
ошибки разрешения — `marketplace_model_key_resolve_failures_total`.
Расчёт выполняется индексатором вне транзакции проектора. Конфликт версии
пропускает устаревший снимок с логом и `marketplace_model_key_conflicts_total`;
остальные записи перестраиваются, актуальное событие досчитывает ключ.

`marketplace model-keys report --out report.json` выгружает количества,
доли (0–1), направления и до 200 примеров совпавших ключей с исходными
атрибутами. Пустое направление в строке счётчиков означает весь каталог.
Файл создаётся с правами 0600.

## Порядок поставки и откат

1. Выпустить `@proshop-app/types`, `@proshop-app/helpers` и `@proshop-app/enums`
   из psdeps, закрепить версию в server/admin и обновить lock-файлы.
   Для этой поставки опубликована версия `0.73.0` (deps PR #68).
2. Применить миграции marketplace и поставку таксономии с проверкой ожидаемой
   версии. Серверный сид версии 3 досевает общие атрибуты штатной командой.
3. Выпустить search и сразу включить `SEARCH_MARKETPLACE_COLLAPSE=true`,
   **до** выката marketplace с `listed = visible`. Поиск дополняет mappings
   существующих поколений; пропавшие партиции не восстанавливаются пустыми.
4. Выпустить серверный издатель, затем marketplace и витрину. Миграция групп
   не нужна: группа без оси сворачивается по `variantsId`, без позиции
   состав упорядочивается по id. Перестроить индекс marketplace.
5. Проверить количество плиток, фасеты и состав карточек при уже включённом
   collapse. Отдельно включить `MARKETPLACE_MODEL_KEYS=true` и выполнить
   reindex для заполнения ключей старых предложений.

Откат группировки: выключить SEARCH_MARKETPLACE_COLLAPSE. Откат наблюдения:
выключить MARKETPLACE_MODEL_KEYS и выполнить reindex для очистки ключей.
Новые поля можно оставить; при удалении миграции сначала откатить использующий
колонки код и задания метрик. Таксономия откатывается штатной командой новой
версией; данные продавцов не переписывались.

Кластеры, production и включение флагов этой работой не затрагивались.
Публикация shared-пакетов выполнена отдельным разрешённым слиянием deps #68. Этапы 3–4 (чужие продавцы и общие карточки моделей) не входят.
