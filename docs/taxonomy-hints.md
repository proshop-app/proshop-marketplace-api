# Источники строковых подсказок

Подсказки строкового атрибута задаются отдельно от его определения в
`dictionaryBindings`. Правило может действовать глобально, для раздела или
для конкретной категории. Оно меняет только набор открытых словарей,
из которых поиск берёт подтверждённые подсказки. Свободные строки карточек,
закрытые enum, значения и метаданные опубликованных атрибутов сохраняются.

Поле `Attribute.dictionary` остаётся базовым источником. Его контракт и
реестр идентичности брендов не меняются: подсказка из другого словаря не
становится идентификатором бренда и не меняет ключи моделей товаров.
Например, марки совместимых автомобилей можно показывать в нужной ветке,
не добавляя их в глобальный identity-реестр `brand`.

## Правило и наследование

```json
{
    "categoryId": "c1",
    "attributeCode": "a1",
    "dictionaries": ["d1", "d2"],
    "mode": "extend"
}
```

`categoryId` отсутствует у глобального правила. Нельзя передавать пустой
параметр категории в URL: отсутствие означает глобальную область, а пустое
или повторённое значение — ошибку.

Источники вычисляются в порядке:

1. `Attribute.dictionary`, если он задан;
2. глобальное правило;
3. правила на пути от корня до выбранной категории, включая её саму.

`extend` добавляет источники к унаследованным. `replace` заменяет набор;
`replace` с `dictionaries: []` отключает подсказки реестра в своей области.
Существующие значения опубликованных товаров остаются отдельным источником
подсказок каталога и не отключаются этим правилом.
Удаление правила возвращает наследование. Правила потомков не объединяются
при запросе родительского раздела.

Список — семантическое множество. Повторы запрещены, перестановка источников
в существующем правиле не создаёт новую версию и сохраняет прежний порядок.
Порядок первого появления нужен только для детерминированного представления;
он не задаёт приоритет словарей. Поиск объединяет источники и устраняет
дубли до ограничения числа результатов.

Общий проверочный пример для Go, поиска и UI —
[d2indings-resolution.v1.json](api/examples/d2indings-resolution.v1.json).
Он включает глобальную область, обе ветки, отключение и отсутствие
объединения правил потомков.

## Ограничения и публикация

- Не более 4096 правил; пара категории и атрибута уникальна.
- Не более 16 словарей в правиле и в итоговом наборе каждой области,
  включая глобальную.
- Атрибут должен иметь тип `string` и использоваться хотя бы одной схемой
  категории в этой области или её потомках.
- Все источники должны существовать и иметь вид `open`. Неизвестные,
  закрытые и повторённые словари отклоняются целиком.
- `extend []`, отсутствующий или `null` список, неизвестные поля JSON,
  некорректные коды и ссылки недопустимы.

Сначала импортируются словари по [контракту импорта](reference-import.md),
затем публикуется правило. Оно не подтверждает кандидатов: выдача появляется
после review и доставки confirmed-записей в поисковую проекцию. Если источник
временно недоступен, поиск не подменяет его неявным словарём по коду атрибута.

## API и общая версия

`GET /api/v1/taxonomy/d2indings` открыт, поддерживает ETag/304 и
всегда возвращает массив, в том числе при отсутствии правил:

```json
{
    "version": 42,
    "dictionaryBindings": []
}
```

Полный операторский снимок также содержит `dictionaryBindings`, когда
правила есть. Старый снимок без этого поля совместим. Отдельный YAML-экспорт
доступен как `GET /api/v1/operator/taxonomy/d2indings`; эта часть
предназначена для просмотра и экспорта, запись правил выполняется узкими
командами ниже.

Категории, атрибуты, схемы и правила имеют одну монотонную версию. Потребитель
скачивает все нужные части и принимает их только при равных версиях; при
гонке повторяет чтение, сохраняя прежний согласованный набор.

Операторская запись использует существующую авторизацию и CSRF-защиту:

```http
PUT /api/v1/operator/taxonomy/d2indings/a1?categoryId=c1
If-Match: "taxonomy-42"
Content-Type: application/json

{"mode":"extend","dictionaries":["d1","d2"]}
```

Удаление одного правила:

```http
DELETE /api/v1/operator/taxonomy/d2indings/a1?categoryId=c1
If-Match: "taxonomy-43"
```

Для глобальной области параметр `categoryId` опускается. Ответ успешной
записи — `{"version":44}` с `ETag: "taxonomy-44"` и
`X-Taxonomy-Version: 44`. Неверная форма — 400, устаревшая версия — 409.
Проверка версии выполняется и для no-op. Перестановка того же множества и
удаление отсутствующего правила с корректной текущей версией не меняют её.

Каждая запись блокирует голову, проверяет весь итоговый набор и открытые
источники, сохраняет новую голову и историю одной транзакцией. Команды
подсказок не перечитывают closed-значения из реестра, не перепроверяют товары
и не создают задачи обновления товарных проекций. Метаданные и изменения
оператора в остальных частях снимка сохраняются.

Существующая загрузка категорий, схем и атрибутов сохраняет правила и
проверяет ссылки в итоговом снимке. Поставка таксономии без
`dictionaryBindings` сохраняет операторские правила; явно переданный
пустой массив в поставке намеренно их очищает. Если новая схема оставляет
правило без используемого атрибута, публикация отклоняется. Старые поставки
не меняют контрольную сумму.

## Исправление ошибочной прежней привязки

Обычная эволюция запрещает смену или удаление существующего
`Attribute.dictionary`. Для ошибочной добавленной открытой подсказки есть
отдельная команда с историческим доказательством:

```bash
go run ./cmd/taxonomy remove-hint \
    --attribute a1 \
    --dictionary d1 \
    --previous-version 40 \
    --expected-version 44
```

Номера в примере условны. До запуска нужно сохранить и проверить текущий
снимок и найти неизменяемую версию истории, где тот же строковый атрибут
ещё не имел словаря. Команда требует точную текущую версию, тот же словарь,
прежний строковый тип и единицу. Она убирает только эту базовую ссылку,
создаёт новую версию и сохраняет все остальные текущие поля, закрытые
значения, метаданные и правила. Она не восстанавливает старый снимок
целиком и не меняет данные реестра или карточек.

Изменение новых правил отменяется обратным PUT или DELETE с актуальным CAS.
Если исправление базовой ссылки нужно отменить, её совместимое добавление
выполняется обычной публикацией атрибутов после проверки снимка. Откат образа
API сам по себе не откатывает данные.
