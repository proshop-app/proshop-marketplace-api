# Единый импорт справочников, версия 1

Оператор загружает один JSON- или YAML-файл в разделе «Словари» админки.
`POST /api/v1/operator/reference/import` создаёт отсутствующие словари и
применяет значения всех словарей одной транзакцией PostgreSQL. API не требует
заранее создавать отдельные словари и не возвращает частичный успех.

Точный контракт — `api/openapi.yaml`: `ReferenceImportPackage`,
`ReferenceImportDictionary`, `ReferenceImportEntry`, `ReferenceImportAlias`,
`ReferenceImportSource`, `ReferenceImportResult`. JSON Schema набора данных
`uno-reference-data/schema/reference-import.v1.schema.json` повторяет этот
контракт; приложение дополнительно проверяет доменные ограничения и коллизии.

## Файл

```yaml
schemaVersion: 1
sources:
    - id: s1
      url: https://example.org/reference-data
      license: CC0-1.0
      version: "1"
dictionaries:
    - code: d1
      kind: open
      release: 1
      entries:
          - canonical: Значение
            status: candidate
            aliases:
                - text: Value
                  kind: locale
                  locale: en
            metadata:
                sourceId: s1
                directions: []
                scope:
                    kind: editorial-candidate
```

JSON представляет тот же объект. Условные значения примера нейтральны и
не являются товарным справочником. В `aliases` используется существующий
доменный `DeliveryAlias`: только `text`, необязательные `kind` и `locale`.
Поля `source` и `weight` относятся к другому, одиночному API вариантов;
в файле поставки они запрещены. Импорт задаёт источнику записи `seed`.

`schemaVersion` равен 1. Источники имеют уникальный `id`, HTTPS URL без
учётных данных, непустую `license` и необязательную `version`. Это
происхождение и лицензия данных; импорт не подтверждает свойства товара
или права на товарный знак. `metadata.sourceId` обязан указывать на источник
пакета; если источник один, поле можно опустить. В metadata сохраняются
`sourceId`, `sourceUrl`, `sourceLicense` и, при наличии, `sourceVersion`.
Остальные поля metadata, включая контекст размеров и ссылки сущностей,
сохраняются. Существующая непустая metadata записи не перезаписывается.

Коды словарей уникальны и соответствуют `^[a-z][a-z0-9_]{0,31}$`.
`kind` — `open` или `closed`; отсутствующий словарь создаётся с обычными
лимитами, normalizer v1 и `identity: false`. Настройки существующего словаря,
включая identity, не меняются; другой kind или normalizer отклоняют пакет.
`release` — целое 1…9007199254740991. В каждом словаре непустой `entries`.

`canonical` и варианты проходят настоящий нормализатор v1: не больше
120 символов и 8 слов; у записи не больше 49 дополнительных вариантов.
metadata — JSON-объект до 4 КиБ вместе с добавленным provenance.
Коллизии ключей между разными записями не сливаются автоматически.
Данные разных размерных систем и разных сущностей требуют проверки
контекста до выпуска поставки, а не объединения только по похожему тексту.

Разрешены `candidate` и `confirmed`. Отсутствующий status означает
`candidate` и у открытого, и у закрытого словаря. Импорт не превращает
новый пул в подтверждённый автоматически. Закрытые кандидаты не становятся
значениями проверки карточек: их нужно подтвердить и отдельно опубликовать
новую версию таксономии.

Тело ограничено **32 МиБ**, пакет — **1000 словарями**, **100000 записями**
суммарно и **10000 источниками**. Неизвестные и повторные ключи, несколько
документов, YAML-якоря, ссылки, специальные теги и вложенность больше 64
отклоняются. Для этого маршрута после проверки оператора действует общий
бюджет загрузки, разбора и транзакции **120 секунд**, ещё 5 секунд оставлено
для ответа после отмены. Обычные таймауты остальных API не меняются.
Шлюз перед API должен пропускать этот путь с телом 32 МиБ и ждать ответ
не меньше 125 секунд; штатный cell edge задаёт для него отдельный лимит 33 МиБ
и proxy read/send timeout 130 секунд. Больший транспортный лимит даёт
приложению вернуть структурированную ошибку файла больше 32 МиБ.

Content-Type — `application/json`, `application/yaml` или
`text/yaml`; передаётся сырой документ, не multipart и не JSON-строка файла.

## Применение и повтор

Все части проверяются до первой записи. Словари блокируются в порядке кодов,
их данные используют существующие правила `reference.Apply`, журнал и outbox.
Ошибка создания, коллизия, несовместимый словарь или конфликт релиза откатывают
весь документ, включая уже созданные заголовки, записи, журнал и события.

SHA-256 считается сервером по каноническому JSON записей после значения
status по умолчанию и добавления provenance. Формат JSON/YAML, пробелы и
порядок ключей metadata сумму не меняют; порядок записей и вариантов значим.
Повтор release с той же суммой ничего не меняет и не создаёт новых событий.
Другие данные того же release, более старый release или повтор ранее
откаченной поставки — 409. Изменение источника также меняет сумму.

Релизы старых CLI-поставок из `deploy/reference` уже заняты и имеют сумму
их `entries.json`. Для нового единого файла над существующими словарями
нужен **следующий** release; перенумеровывать уже применённые поставки нельзя.
CLI-формат `manifest.json` + `entries.json` остаётся прежним.

Новый релиз добавляет значения и недостающие варианты, может подтвердить
кандидата, если файл явно содержит confirmed. Отклонённые и выведенные
оператором записи пропускаются; переименования и непустая metadata оператора
сохраняются существующим механизмом поставки. Отсутствие записи в файле
не удаляет её. Это пополнение, а не замена всего реестра.

Импорт запускается только явной загрузкой оператором. Запуск API,
перезапуск контейнера и обновление UI ничего не импортируют и не очищают.
Импорт не меняет `attribute.dictionary`, схемы и публикацию taxonomy,
не ослабляет `CheckEvolution`. Подключение новых справочников к существующим
атрибутам требует отдельного согласованного изменения контракта таксономии.
Откат приложения не откатывает данные; исправление состава выпускается
следующим релизом с сохранением решений оператора.

## Операторский API

Все маршруты используют существующую операторскую авторизацию. Для
cookie-мутаций нужны разрешённый Origin и `X-Requested-With: KvazarOperator`;
служебный операторский Bearer разрешён прежней политикой. Read-token
потребителя не даёт доступа ни к этому списку, ни к импорту и правкам.
Секреты не передаются в файл и не встраиваются в браузер.

- `GET /api/v1/operator/reference` — `{schemaVersion: 1, dictionaries}`;
  у словаря `code`, `kind`, `revision`, `entries`, `candidates`.
- `GET /api/v1/operator/reference/{dict}/entries?status=candidate&limit=50&offset=0`
  — `{schemaVersion, revision, total, entries}`; limit до 200.
- `GET /api/v1/operator/reference/{dict}/entries/{id}` — прежний
  `ReferenceEntryResponse`, ETag с ревизией записи.
- `PATCH /api/v1/operator/reference/{dict}/entries/{id}` — прежняя правка:
  `{status: confirmed|rejected, reason?}` для кандидата и `If-Match: "12"`
  из ETag. Устаревшая ревизия — 409; нужно перечитать запись.
- `POST /api/v1/operator/reference/import` — один файл пакета.

Ответ импорта:

```json
{
    "schemaVersion": 1,
    "dictionaries": [
        {
            "code": "d1",
            "created": true,
            "release": 1,
            "revision": 1,
            "changed": true,
            "createdEntries": 1,
            "updatedEntries": 0,
            "skippedEntries": 0
        }
    ]
}
```

`created` относится к заголовку словаря. `changed` означает применение нового
релиза; при повторе оба false и счётчики изменений нулевые. Ответ 400 означает
неверный документ или доменные ограничения, 401/403 — доступ/CSRF, 409 —
конфликт релиза, настроек или занятого ключа. Превышение бюджета — 503
`reference.import_timeout`. Обрыв ответа может произойти уже после коммита;
нужно повторить тот же файл, чей релиз и сумма обеспечивают идемпотентность.
Ошибки проходят общую таблицу
`pkg/errs`; сообщения драйвера БД клиенту не раскрываются.

## Явная привязка подсказок в таксономии

Импорт сам не меняет атрибуты. Для проверенного пакета `reference-v2.json`
выпущена отдельная [поставка таксономии 7](taxonomy-releases.md#поставка-7-открытые-подсказки-существующих-строк):
66 безопасных строковых привязок с теми же кодами. Пакет импортируется до
`taxonomy apply`; отсутствие нужного открытого словаря отклоняет публикацию.
Кандидаты становятся подсказками только после решения оператора. Неизвестные
строки товаров по-прежнему допустимы, откат таксономии не удаляет записи реестра.


Для новых операторских привязок используется отдельный механизм
[dictionaryBindings](taxonomy-hints.md): несколько открытых источников,
глобальная область или путь категории, `extend`/`replace`, узкие PUT/DELETE
с общей версией. Он сохраняет базовую идентичность бренда и closed-значения.
