# Единый импорт справочников, версия 2

Оператор загружает один JSON- или YAML-файл в разделе «Словари» админки.
`POST /api/v1/operator/reference/import` создаёт отсутствующие словари и
применяет значения всех словарей одной транзакцией PostgreSQL. API не требует
заранее создавать отдельные словари и не возвращает частичный успех.

Точный контракт — `api/openapi.yaml`: `ReferenceImportPackage`,
`ReferenceImportDictionary`, `ReferenceImportEntry`, `ReferenceImportAlias`,
`ReferenceImportSource`, `ReferenceImportResult`. JSON Schema набора данных
в uno-reference-data должна соответствовать версии 2 этого контракта.
Версия 1 отвергается. Полный пакет выпускается там как
`exports/marketplace-bootstrap.json`; площадка не хранит его копию.
Приложение дополнительно проверяет доменные ограничения и коллизии.

## Файл

```yaml
schemaVersion: 2
sources:
    - id: s1
      url: https://example.org/reference-data
      license: CC0-1.0
      version: "1"
dictionaries:
    - code: d1
      kind: open
      identity: false
      aliasKinds: [spelling, translit, abbreviation, former, locale]
      limits:
          maxEntries: 1000000
          maxAliases: 50
          maxAliasLength: 120
          maxAliasWords: 8
          normalizer: v1
      release: 1
      entries:
          - canonical: Значение
            status: candidate
            aliases:
                - text: Value
                  kind: locale
                  locale: en
            metadata:
                sourceId: s1
                directions: []
                scope:
                    kind: editorial-candidate
```

JSON представляет тот же объект. Условные значения примера нейтральны и
не являются товарным справочником. В `aliases` используется существующий
доменный `DeliveryAlias`: только `text`, необязательные `kind` и `locale`.
Поля `source` и `weight` относятся к другому, одиночному API вариантов;
в файле поставки они запрещены. Импорт задаёт источнику записи `seed`.

`schemaVersion` равен 2. Источники имеют уникальный `id`, HTTPS URL без
учётных данных, непустую `license` и необязательную `version`. Это
происхождение и лицензия данных; импорт не подтверждает свойства товара
или права на товарный знак. `metadata.sourceId` обязан указывать на источник
пакета; если источник один, поле можно опустить. В metadata сохраняются
`sourceId`, `sourceUrl`, `sourceLicense` и, при наличии, `sourceVersion`.
Остальные поля metadata, включая контекст размеров и ссылки сущностей,
сохраняются. Существующая непустая metadata записи не перезаписывается.

Коды словарей уникальны и соответствуют `^[a-z][a-z0-9_]{0,31}$`.
`kind` — `open` или `closed`. Заголовок задаётся целиком: обязательны `code`,
`kind`, `identity`, `aliasKinds`, `limits`, `release`, `entries`.
`identity` — обязательный boolean; отсутствие или null — `reference.invalid_settings`.
Он не наследуется от прежней настройки.
`aliasKinds` — непустой массив уникальных значений `spelling`, `translit`,
`abbreviation`, `former`, `locale`; `spelling` обязателен для канонического имени.
Порядок aliasKinds незначим и перед вычислением checksum сортируется.

`limits` — объект с пятью обязательными полями:

| Поле | Значение |
|---|---|
| `maxEntries` | Целое 1…1000000, предел рабочих записей словаря |
| `maxAliases` | Целое 1…50, включая канонический вариант |
| `maxAliasLength` | Целое 1…120, символы после схлопывания пробелов |
| `maxAliasWords` | Целое 1…8, слова написания |
| `normalizer` | Только строка `v1`; это версия алгоритма, не версия пакета |

Новые заголовки создаются с этими настройками. Существующие обновляются
в транзакции импорта, после проверки номера выпуска и checksum.
Служебные `revision`, `entries` (счётчик), timestamps не загружаются из пакета.
Поле `entries` пакета всегда означает массив записей.

| Настройка | Применение | Отказ |
|---|---|---|
| `kind`, `identity` | Создание или изменение пустого словаря | При наличии записей значение нельзя менять: меняются правила перечисления и идентичности |
| `maxEntries` | В пределах контракта, не ниже текущего счётчика | Новый предел ниже числа записей |
| `maxAliases`, `maxAliasLength`, `maxAliasWords` | Любое допустимое значение для пустого; увеличение для заполненного | Уменьшение для заполненного требует отдельного аудита уже сохранённых написаний |
| `aliasKinds` | Допустимый набор для пустого; расширение для заполненного | Удаление вида при наличии записей может сделать существующие варианты недопустимыми |
| `normalizer` | `v1` | Другой алгоритм не поддержан; существующий словарь с другим normalizer требует миграции ключей |

Некорректный заголовок — 400 `reference.invalid_settings`; опасное изменение —
409 `reference.settings_conflict`; другой normalizer существующего словаря —
409 `reference.normalizer_mismatch`. Проверка записей использует лимиты и виды
вариантов из пакета, а не настройки по умолчанию.

`release` — целое 1…9007199254740991. `entries` — обязательный массив (не `null`).
Для `open` допустим `[]`; для `closed` требуется хотя бы одна запись.

`canonical` и варианты проходят настоящий нормализатор v1: не больше
120 символов и 8 слов; у записи не больше 49 дополнительных вариантов.
metadata — JSON-объект до 4 КиБ вместе с добавленным provenance.
Коллизии ключей между разными записями не сливаются автоматически.
Данные разных размерных систем и разных сущностей требуют проверки
контекста до выпуска поставки, а не объединения только по похожему тексту.

Разрешены `candidate` и `confirmed`. Отсутствующий status означает
`candidate` и у открытого, и у закрытого словаря. Импорт не превращает
новый пул в подтверждённый автоматически. Закрытые кандидаты не становятся
значениями проверки карточек: их нужно подтвердить и отдельно опубликовать
новую версию таксономии.

Тело ограничено **32 МиБ**, пакет — **1000 словарями**, **100000 записями**
суммарно и **10000 источниками**. Неизвестные и повторные ключи, несколько
документов, YAML-якоря, ссылки, специальные теги и вложенность больше 64
отклоняются. Для этого маршрута после проверки оператора действует общий
бюджет загрузки, разбора и транзакции **120 секунд**, ещё 5 секунд оставлено
для ответа после отмены. Обычные таймауты остальных API не меняются.
Шлюз перед API должен пропускать этот путь с телом 32 МиБ и ждать ответ
не меньше 125 секунд; штатный cell edge задаёт для него отдельный лимит 33 МиБ
и proxy read/send timeout 130 секунд. Больший транспортный лимит даёт
приложению вернуть структурированную ошибку файла больше 32 МиБ.

Content-Type — `application/json`, `application/yaml` или
`text/yaml`; передаётся сырой документ, не multipart и не JSON-строка файла.

## Применение и повтор

Все части проверяются до первой записи. Словари блокируются в порядке кодов,
их данные используют существующие правила `reference.Apply`, журнал и outbox.
Ошибка создания, коллизия, несовместимый словарь или конфликт релиза откатывают
весь документ, включая уже созданные заголовки, записи, журнал и события.

SHA-256 считается сервером по каноническому JSON объекта
`{"settings": {"kind", "identity", "aliasKinds", "limits"}, "entries": [...]}`
после применения status по умолчанию, добавления provenance и сортировки aliasKinds.
Порядок полей settings: kind, identity, aliasKinds, limits; внутри limits:
maxEntries, maxAliases, maxAliasLength, maxAliasWords, normalizer.
Сериализация — `encoding/json` модели Go: canonical, status, затем непустые
aliases и metadata; ключи объектов metadata сортируются. Сумму вычисляет площадка,
отправитель её не передаёт. Все настройки заголовка входят в сумму. Формат JSON/YAML, пробелы и
порядок ключей metadata сумму не меняют; порядок записей и вариантов значим.
Повтор release с той же суммой ничего не меняет и не создаёт новых событий.
Другие данные или настройки того же release, а также более старый release — 409.
Изменение источника также меняет сумму.

Релиз относится одновременно к заголовку и записям. Изменённые настройки
при том же release дают конфликт суммы, даже если массив записей не менялся.
Изменение только настроек занимает новый выпуск, но не создаёт ревизий записей
и событий их изменения. Повтор пакета ничего не меняет.

Журнал `reference.deliveries` сохраняется. Номера ранее импортированных выпусков
уже заняты: для перехода с прежнего формата нужен следующий release каждого
словаря. Исторические миграции 00027/00030 не меняются; заголовки из них обновляются
пакетом по тем же правилам. Старые команды check/apply/apply-all/rollback удалены.

Новый релиз добавляет значения и недостающие варианты, может подтвердить
кандидата, если файл явно содержит confirmed. Отклонённые и выведенные
оператором записи пропускаются; переименования и непустая metadata оператора
сохраняются существующим механизмом поставки. Отсутствие записи в файле
не удаляет её. Это пополнение, а не замена всего реестра.

Импорт запускается только явной загрузкой оператором. Запуск API,
перезапуск контейнера и обновление UI ничего не импортируют и не очищают.
Импорт не меняет `attribute.dictionary`, схемы и публикацию taxonomy,
не ослабляет `CheckEvolution`. Подключение новых справочников к существующим
атрибутам требует отдельного согласованного изменения контракта таксономии.
Откат приложения не откатывает данные; исправление состава выпускается
следующим релизом с сохранением решений оператора.

## Операторский API

Все маршруты используют существующую операторскую авторизацию. Для
cookie-мутаций нужны разрешённый Origin и `X-Requested-With: KvazarOperator`;
служебный операторский Bearer разрешён прежней политикой. Read-token
потребителя не даёт доступа ни к этому списку, ни к импорту и правкам.
Секреты не передаются в файл и не встраиваются в браузер.

- `GET /api/v1/operator/reference` — `{schemaVersion: 1, dictionaries}`;
  у словаря `code`, `kind`, `revision`, `entries`, `candidates`.
- `GET /api/v1/operator/reference/{dict}/entries?status=candidate&limit=50&offset=0`
  — `{schemaVersion, revision, total, entries}`; limit до 200.
- `GET /api/v1/operator/reference/{dict}/entries/{id}` — прежний
  `ReferenceEntryResponse`, ETag с ревизией записи.
- `PATCH /api/v1/operator/reference/{dict}/entries/{id}` — прежняя правка:
  `{status: confirmed|rejected, reason?}` для кандидата и `If-Match: "12"`
  из ETag. Устаревшая ревизия — 409; нужно перечитать запись.
- `POST /api/v1/operator/reference/import` — один файл пакета.

Ответ импорта:

```json
{
    "schemaVersion": 2,
    "dictionaries": [
        {
            "code": "d1",
            "created": true,
            "release": 1,
            "revision": 1,
            "changed": true,
            "createdEntries": 1,
            "updatedEntries": 0,
            "skippedEntries": 0
        }
    ]
}
```

`created` относится к заголовку словаря. `changed` означает применение нового
релиза; при повторе оба false и счётчики изменений нулевые. Ответ 400 означает
неверный документ или доменные ограничения, 401/403 — доступ/CSRF, 409 —
конфликт релиза, настроек или занятого ключа. Превышение бюджета — 503
`reference.import_timeout`. Обрыв ответа может произойти уже после коммита;
нужно повторить тот же файл, чей релиз и сумма обеспечивают идемпотентность.
Ошибки проходят общую таблицу
`pkg/errs`; сообщения драйвера БД клиенту не раскрываются.

## Явная привязка подсказок в таксономии

Импорт сам не меняет атрибуты. Для исторического пакета подсказок
была выпущена отдельная [поставка таксономии 7](taxonomy-releases.md#поставка-7-открытые-подсказки-существующих-строк):
66 безопасных строковых привязок с теми же кодами. Пакет импортируется до
`taxonomy apply`; отсутствие нужного открытого словаря отклоняет публикацию.
Кандидаты становятся подсказками только после решения оператора. Неизвестные
строки товаров по-прежнему допустимы, откат таксономии не удаляет записи реестра.


Для новых операторских привязок используется отдельный механизм
[dictionaryBindings](taxonomy-hints.md): несколько открытых источников,
глобальная область или путь категории, `extend`/`replace`, узкие PUT/DELETE
с общей версией. Он сохраняет базовую идентичность бренда и closed-значения.

## Пустой открытый словарь и обучение

Пакет с `kind: open, entries: []` сохраняет заголовок словаря и номер поставки.
Повтор того же пакета — no-op, включая повтор после появления кандидатов:
существующие записи не удаляются. Отсутствующий `entries` и `null` недопустимы.
Источником определения может быть определение атрибута таксономии в `sources`;
фиктивные записи и metadata для них не создаются. Происхождение определения
сохраняется в файле поставки и его отчёте; реестр хранит provenance записей,
а отдельного поля provenance заголовка в контракте нет.

Таксономия принимает ссылку string-атрибута на существующий пустой open.
Полный снимок реестра для поиска возвращает ревизию 0 и пустые массивы.
Само создание заголовка не посылает событие изменения записей. Сбор кандидатов
по опубликованным базовым/контекстным привязкам запрашивает значения каталога,
создаёт первую запись `candidate` с источником `catalog`, повышает ревизию до 1
и ставит в outbox событие для `catalog.reference.changed` (0 → 1).
Очередь оператора показывает эту запись; дельта снимка после 0 содержит её.
Кандидат не становится confirmed автоматически. Наличие закрытого словаря
недостаточно: для публикации enum нужны confirmed и точные значения всех
ключей `valuesMeta` и непустых `searchTermsByValue`.

## Разработка и стенд

`make reference-import` и `make dev` используют:

```make
REFERENCE_DATA ?= ../uno-reference-data
REFERENCE_PACKAGE ?= $(REFERENCE_DATA)/exports/marketplace-bootstrap.json
```

Это пути разработчика, не конфигурация сервиса. Нет checkout или файла — цель
падает с подсказкой. Пакет должен быть подготовлен в uno-reference-data до запуска.
CLI принимает JSON; операторский HTTP принимает JSON и YAML.
На стенде оператор импортирует пакет после миграций и до публикации таксономии.
Старый Job `marketplace-reference`, читающий файлы из образа, должен быть отключён.
