# Определение города без передачи IP наружу

`GET /api/v1/city`: доверенный clientIP → локальный mmap DB-IP City Lite → координаты
(только страна RU) → ближайший город встроенного HFLabs/city. Английские названия
из MMDB не декодируются и не участвуют в сопоставлении. Справочник, источник,
версия, checksum и лицензия: [geocity/data](../geocity/data/README.md).

Пространственный индекс — сбалансированное k-d дерево трёхмерных единичных векторов:
сферическое расстояние без проблем долготы/полюсов. Строится один раз при старте,
1100 записей / 83 региона; запрос не перебирает CSV. Радиус 50 км выбран по выборке
135 публичных домашних/операторских probes RIPE Atlas: p95 расстояния координаты
DB-IP до ближайшего города 45 км. Дальше — ручной выбор. Это фильтр далёких координат,
а не гарантия точности: на этой выборке город совпал у 64/135, регион у 84/135.
Эталон probes — ближайший город к публичным координатам, не проверенный домашний адрес.

Ответ — `{city,country,label,region,regionCode,fiasId,kladrId}`; последние поля есть
при найденном городе. Пустой city/country означает «не определён». Подтверждение
на web сохраняет готовый объект, без запроса подсказок и сравнения названий.
Ручные подсказки остаются прежними: запрос через клиент сервера магазинов к DaData.

## Приватность и адрес прокси

На запрос определения — 0 SQL, 0 Redis, 0 исходящих HTTP. IP используется только
как аргумент поиска и не сохраняется, не хешируется в ключ, не попадает в INFO/WARN.
Удалены ip-api, его Redis-кэш, кэш отказа и общая пауза; отдельный endpoint `/region`
и существующие лимиты входа/ручных подсказок этим изменением не меняются.
В браузере остаются существующие cookies выбора и сессионного результата города,
без IP. Сервер не строит собственную базу посетителей.

Единственная точка извлечения IP — `interfaces/http/clientip.go`. За Caddy →
cell-proxy на kind `HTTP_TRUST_PROXY=2`: адрес берётся справа, левую подстановку
клиента игнорируем. В production число настраивается по фактической цепочке,
а не копируется из kind. Для SSR допускается более короткая доверенная цепочка.
RFC1918, loopback, CGNAT, link-local, IPv6 ULA и зарезервированные диапазоны дают
пустой результат до открытия/поиска в MMDB.

`MARKETPLACE_CITY_DEV_CLIENT_IP` подменяет только частный адрес, только при
`MARKETPLACE_ENV=development`. По умолчанию production; с этой переменной в production
сервис не стартует. В kind используется публичный DNS Яндекса 77.88.8.8 (Москва в
проверенной DB-IP 2026-11): локальный адрес хоста не выдаётся за геолокацию посетителя.
Ни выбранный вручную город, ни адрес для лимитов такой подменой не меняются.

## Поставка и обновление

Источник: https://db-ip.com/db/download/ip-to-city-lite — CC BY 4.0;
месячный HTTPS URL `https://download.db-ip.com/free/dbip-city-lite-YYYY-MM.mmdb.gz`.
Постоянный URL «latest» и официальный SHA-256 не подтверждены. На странице есть
MD5/SHA-1 распакованного MMDB. Загрузчик использует TLS, gzip CRC, проверку дерева
MMDB и контрольные записи IPv4/IPv6; published MD5/SHA-1 автоматически не парсит.
Файл ноября 2026: 126873350 байт (121 МиБ), архив 60125343 байта.
В git и образе файла DB-IP нет. Библиотека maxminddb-golang v1.13.1 — ISC,
Go 1.23; уведомление лицензии находится в образе `/licenses`.

Отдельный бинарник `/geoip-update --file /geoip/dbip-city-lite.mmdb [--month YYYY-MM]`:

1. Скачивает только официальный HTTPS host download.db-ip.com, без proxy окружения
   и перенаправлений. Срок клиента 10 минут, распаковка ограничена 512 МиБ.
2. Пишет временный файл в том же каталоге, проверяет формат, IPv4+IPv6, дерево,
   записи публичных DNS IPv4/IPv6: есть страна и допустимые координаты. Страна anycast
   не фиксируется: в ноябрьском DB-IP Google IPv6 относится к CA, а не US.
   Поставка старше действующей отвергается.
3. Sync/close → атомарный rename. Временный файл при отказе удаляется, прежний
   остаётся. UID API и Job одинаков — 65532; временный и итоговый файл имеют 0600.

CronJob чарта marketplace запускается 3-го числа месяца в 03:15 UTC (запас после
публикации 1-го), concurrencyPolicy Forbid, deadline 900 с, две повторные попытки.
PVC сохраняется при удалении релиза. API монтирует каталог readOnly, без subPath.
Раз в 5 минут проверяется inode/mtime; новый mmap открывается до смены читателей,
старый закрывается после завершения его чтений. Нет stat на запрос покупателя.
Полную Verify делает Job; API повторяет проверку метаданных при открытии.
Сбой не останавливает старый mmap. Если файла ещё нет — 503 city.unavailable и
ручной выбор; сервер поднимется, подхватит первую успешную поставку без перезапуска.

Метрики API: `marketplace_geoip_database_build_timestamp_seconds` (0 — нет базы),
`marketplace_geoip_reload_failures_total`. Возраст в секундах:
`time() - marketplace_geoip_database_build_timestamp_seconds`; ноль проверять отдельно.
Неудачная загрузка Job завершается кодом 1 с ERROR; прежняя дата сборки не меняется,
возраст продолжает расти. Проверять также Failed у Job/CronJob.

Чарт не даёт API выхода в Интернет для города. Для Job — DNS и HTTPS только к
IP-адресам download.db-ip.com, полученным `scripts/geoip-egress-values.py`.
Стандартная Kubernetes NetworkPolicy не умеет FQDN: CIDR фиксируются при выкате,
их нужно обновлять при смене DNS; CDN может делить IP с другими доменами. Фиксированный
host, проверка TLS и запрет redirect обеспечиваются самим загрузчиком. FQDN-гарантия
на уровне CNI потребует выбранного сетевого решения, а не выдуманной стандартной policy.
Kind по-прежнему использует свой CNI; фактическое enforcement этим заданием не проверялось.

Точные команды и порядок обновления чарта — `proshop-platform/docs/runbook.md`,
раздел «Локальная GeoIP маркетплейса»; работающий стенд этим изменением не затрагивался.
