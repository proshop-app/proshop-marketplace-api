# CLAUDE.md — правила кода proshop-marketplace

Backend федеративного маркетплейса платформы Proshop на Go. Проект и решения —
`proshop-server/docs/marketplace-mvp.md` (§3 раскладка, §4 данные, §8 стыки,
§10 проверка, §11 план), стыки с платформой — `docs/platform-ecosystem.md`
§8–§11, требования надёжности — `docs/shared-platform-plan.md` §15.
Реестр справочных сущностей (модуль `reference`: схема, контракты снимка,
`resolve`, события и поставки) — `docs/reference.md`.

## Слои

```
domain ← application ← interfaces, infrastructure        сборка графа — cmd/ руками
```

| Слой | Что лежит | Что можно импортировать |
|---|---|---|
| `pkg/` | деньги, идентификаторы, ошибки с кодами | только стандартную библиотеку и `pkg/` |
| `internal/domain/<контекст>` | агрегаты, объекты-значения, правила, `errors.go`, `repository.go` (только интерфейсы) | стандартную библиотеку, `pkg/`, другие пакеты домена |
| `internal/application/<контекст>` | сценарии: команды, запросы, транзакции через `UnitOfWork` | домен, `pkg/`, `application/ports`; **не** `infrastructure`, `interfaces`, `config` |
| `internal/application/ports` | порты: `UnitOfWork`/`Tx`, outbox, inbox, индексы, часы, сессии и лимиты, звонок (`CallCheck`), API сервера (`PlatformAPI`), справочники перевозчиков | домен, `pkg/` |
| `internal/application/fake` | реализации портов в памяти для тестов | как приложение |
| `internal/infrastructure/*` | реализации портов: PostgreSQL, OpenSearch, Kafka, Redis, sms.ru, СДЭК, Яндекс Доставка, API сервера, телеметрия | приложение, домен, `pkg/`, библиотеки; **не** `interfaces`, `config` |
| `internal/interfaces/*` | HTTP, обработчики Kafka, фоновые циклы: разбор → сценарий → ответ | приложение, домен, `pkg/`, библиотеки; **не** `infrastructure`, `config` |
| `internal/config` | окружение с проверкой на старте | читает только `cmd/` |
| `cmd/` | сборка зависимостей без DI-магии | всё |

Закон слоёв держат два сторожа, нарушение — красный CI:
`internal/architecture/layers_test.go` (полный граф `go list -deps`, включая
импорты тестов домена и приложения) и `depguard` в `.golangci.yml`.

Контексты заводятся в свою неделю. Пустых каталогов «на вырост» нет:
`participant`, `catalog` — с недели 1, `buyer`, `cart`, `delivery`,
`checkout` — с недели 2; `order` — снимок покупок с недели 3.
Оплата — вариант В: один платёж за покупку (решение владельца 2026-11-07).
Сейчас работает болванка без движения денег; боевая оплата — сплит ЮKassa после согласования.
Статусы, отправка и возвраты остаются по группам.

## Раскладка кода

- В файле сначала `const`, `var` и `type`, потом функции и методы. Новый
  тип в конце файла — красный тест.
- `cmd/*/main.go` — только `func main`. Таблица команд и `run` — в
  `cli.go`, сборка графа — в `server.go`, `infrastructure.go`, команды — в
  `commands.go`.
- Строка — не длиннее 120 символов (табуляция — 4).
- Многострочный литерал или вызов — по полю или аргументу на строку; либо
  всё на строке скобки, а многострочным остаётся только последний аргумент:
  `f(ctx, T{ … })`. Длинное сообщение ошибки или составной аргумент — в
  переменную, не в перенос.
- SQL репозиториев — именованные константы в начале файла, в `SET` — по
  колонке на строку. Репозитории разложены по агрегатам, общие помощники —
  `postgres/values.go`.

Правила держат `internal/architecture/layout_test.go` (порядок объявлений,
`main.go`, «по элементу на строку») и `lll` в `.golangci.yml`.

## Деньги

- Только `pkg/money.Money` — целые копейки. Сложение и вычитание —
  `Add`/`Sub`, они ловят переполнение. `float64` для денег нет нигде.
- Цены из событий сервера приходят рублями (`199.99`) — разбираются
  `money.ParseRubles` из текста `json.Number`, без float; дробь меньше копейки
  округляется половиной от нуля.
- В базе — `bigint` копеек, в индексе — `long`, в API — целые копейки.

## Агрегаты и хранение

- Агрегат меняется только своими методами; методы возвращают, изменилось
  ли состояние, повтор — не изменение.
- Агрегат помнит исходное состояние (`Origin`/`OriginVersion`); версия
  растёт на единицу за сохранение. Репозиторий обновляет условно:
  `UPDATE … WHERE status = исходный AND version = исходная`, ноль строк —
  типизированный конфликт, не тихая перезапись. После сохранения —
  `MarkSaved`.
- Одна транзакция на сценарий: `UnitOfWork.Do`. Отметка события в
  `processed_events`, изменение агрегата и задача в `outbox` фиксируются
  вместе. Проглоченная ошибка запроса внутри транзакции — ошибка сценария,
  база всё равно откатит.
- Проекции из событий упорядочены ревизией источника (снимки) или временем
  публикации (остаток, цена); старое и повтор не применяются.
- Миграции goose — `postgres/migrations`. Номер новой — следующий за последним
  в свежем `origin/master`; если номер успели занять в master — перенумеровать
  до влития. Применённую где-либо миграцию не переименовывать и не править:
  goose помнит только номер. Повтор номера и файл без номера — красный
  `make test`.

## Порты и внешние вызовы

- Любой вызов наружу (база, индекс, брокер, сервер, sms.ru,
  перевозчики) — за портом в `application/ports`, реализация — в
  `infrastructure`. Учётные данные внешних сервисов — только из окружения.
- Контракт с внутренним API сервера — `docs/server-contract.md`; клиент
  `infrastructure/platformapi` меняется только вместе с ним.
- Тесты приложения и транспорта — на `application/fake`.
- Интеграции с настоящими сервисами — только `internal/infrastructure/**/*_test.go`
  под тегом `integration`, на compose: `make test-integration`. Каждый тест
  заводит свою базу (`postgres/pgtest`), свой алиас индекса, свои топики и
  группу и убирает их за собой. Миграции в тестах применяются с нуля.
- Адаптеры внешних API (sms.ru, СДЭК, Яндекс, сервер) тестируются на
  `testdata` — записанных ответах — через `httptest`. Живой вызов — только
  отдельным тестом под флагом окружения (`SMSRU_LIVE_TEST=1`,
  `CDEK_LIVE_TEST=1`, `YANDEX_LIVE_TEST=1`) с ключами из окружения.

## Ошибки

- `pkg/errs`: код класса (`invalid`, `not_found`, `conflict`,
  `unauthorized`, `too_many_requests`, `unavailable`, `internal`) и стабильный ключ
  `контекст.причина`. Доменные ошибки объявлены в `errors.go` контекста;
  `errors.Is` сравнивает по ключу, `WithMessage`/`Wrap` его сохраняют.
- HTTP переводит ошибку в ответ одной таблицей
  (`internal/interfaces/http/errors.go`, `statusByCode`). Внутренние ошибки
  клиенту не раскрываются, пишутся в журнал с `requestId`.
- Kafka: ошибка класса `invalid` — сообщение в отравленные (`parked_events`)
  с метрикой и коммит; остальные — повтор с паузой; после
  `KAFKA_MAX_ATTEMPTS` при живой базе — в отравленные с причиной
  `attempts_exhausted`; при недоступной базе сообщение ждёт.

## События и индекс

- Магазин сообщения: проекции — ключ `["tenantId","id"]` и тело, остаток и
  цена — заголовок `x-tenant`, реестр — тело; заголовок, если есть, обязан
  совпасть. Нет магазина или расхождение — в отравленные.
- Идентификатор события для дедупа — `<topic>:<partition>:<offset>`.
  Коммит позиции — только после записи итога.
- Топиками владеет сервер установки. Читатель подписывается только на
  существующие топики и не заводит их у брокера (запрос метаданных без
  списка топиков); появившийся топик подхватывается без перезапуска.
- Индекс предложений — производная проекции в общем `proshop-search`.
  Backend обращается к нему через `infrastructure/searchapi` и порт `OfferIndex`;
  прямой OpenSearch здесь обслуживает только геоиндекс пунктов выдачи.
  Документ пишется с внешней версией `external_gte` = сумма версий товара, сигналов, участника и записи
  реестра: поздний снимок не проигрывает раннему. Скрытое предложение —
  документ без карточки. Перестроение — новое поколение, атомарная смена
  рабочего поколения, догоняющий проход. CLI и фоновые пересборки используют
  одну PostgreSQL advisory lock. Служебный контракт поиска имеет версию 4
  (`rating`, `sort=rating`, `offer.assets`); неподдерживаемый контракт — отказ, старая схема
  индекса — пересборка.
- Outbox: задача ставится в транзакции изменения, разбор берёт задачи с
  арендой, `FOR UPDATE SKIP LOCKED`, не больше `OUTBOX_PER_TENANT` на магазин
  за пачку — шумный магазин не задерживает чужие.
- Метрики и журналы с меткой `tenant`/`tenantId` там, где речь о магазине.

## Покупатель

- Вход — звонок на номер sms.ru; в разработке — песочница
  (`SMSRU_MODE=sandbox`), она подтверждает любой номер сама.
- Access — JWT identity-hub в `__Host-mp_access`; обычная проверка без Redis/userinfo.
  В Redis только зашифрованный refresh, браузерный указатель — `__Host-mp_key`.
  Оператор использует отдельный client realm platform. Полный контракт —
  `docs/identity-jwt-cookies.md`. Старые opaque-токены не принимаются.
- Лимиты входа — на номер и на адрес клиента, окно в Redis; превышение —
  `too_many_requests` с подсказкой, когда повторить.
- Адрес клиента (лимиты, регион) — только `clientIP` в `interfaces/http`: по
  числу доверенных прокси `HTTP_TRUST_PROXY` справа, левое звено
  `X-Forwarded-For` задаёт сам клиент.
- `buyerId` лежит в контексте запроса и попадает в журнал.

## Универсальность

Платформа универсальна: ни одной константы, умолчания, фикстуры или
словаря, завязанных на конкретный магазин, город или товарную категорию.
Анализатор поиска — русская морфология без тематических словарей. В тестах —
нейтральные `t1`, `p1`, «Товар», «Магазин».

## Тесты

| Что | Где | Команда |
|---|---|---|
| домен, `pkg` | рядом с кодом, без инфраструктуры | `make test` |
| сценарии приложения, HTTP, Kafka-разбор, циклы | на `application/fake` | `make test` |
| сторож слоистости и раскладки кода | `internal/architecture` | `make test` |
| адаптеры внешних API | `internal/infrastructure/**`, на `testdata` | `make test` |
| репозитории, индекс, консьюмеры, сквозной путь | `internal/infrastructure/**`, тег `integration` | `make test-integration` |

`make test` идёт с `-race`. Красное чинится, не пропускается.

## Одна команда

`make dev` — compose (PostgreSQL 16, OpenSearch, Kafka KRaft, Redis),
миграции и сервис с перезапуском (air). Остальное: `make test`,
`make test-integration`, `make lint`, `make migrate`, `make reindex`,
`make refresh-pickup-points`, `make build`, `make image`. Инструменты не ставятся глобально: golangci-lint
и air — `go run` с версиями из `Makefile`, goose встроен в `cmd/migrate`.
`GOTOOLCHAIN=local`: проект собирается go1.23.2.

## Код и коммиты

- Комментарии и сообщения — по-русски, объясняют «почему».
- Нет закомментированного кода, TODO без задачи, пустых пакетов, мёртвых
  функций.
- Коммиты и описания PR — по-русски. В master не пушить: ветка и PR.
