# Служебная запись предложений в поиск

`POST /api/v1/internal/marketplace/offers` принимает до 200 предложений
и до 4 МиБ JSON за запрос. HTTP 204 подтверждает весь подпакет.
Если переполнена часть рабочего поколения, поиск отвечает HTTP 503:

```json
{
  "code": "GENERATION_CAPACITY",
  "deferredOffers": [
    {
      "tenantId": "shop-7",
      "productId": "p-42",
      "part": "marketplace-offers-uno-g20261121-p01-data",
      "reason": "roots"
    }
  ]
}
```

`deferredOffers` перечисляет все отложенные записи данного HTTP-запроса.
Предложение определяется парой `tenantId` и `productId`. `part` называет
физическую часть рабочего поколения, `reason` — порог `roots`, `engineDocs`
или `primaryBytes`. Ответ ограничен 200 записями и 384 КиБ.

Клиент продолжает отправлять следующие подпакеты после `GENERATION_CAPACITY`.
Outbox `catalog.offer.sync` завершает задачи подтверждённых предложений
и откладывает остальные. В назначенный срок он читает актуальные версии
из PostgreSQL. Пауза начинается с секунды и удваивается до 10 минут.
Если код распознан, а полного корректного списка в ответе нет, повтору
подлежит весь соответствующий подпакет. Так же обрабатываются ответы старого
поиска с одним полем `code`. Для прочих ошибок действуют обычные правила
повтора. Запись в явно выбранное строящееся поколение использует
`POST /api/v1/internal/marketplace/generations/{generation}/offers`.
